# Сценарии Expert Memory Market

Маркет особенно полезен, когда покупателю нужен прикладной ответ, но до
разблокировки он обязан проверить авторство, доказательства и цену. Эти
сценарии используют уже работающие контракты: публичные listings, pass,
metered reads, publisher split и проверяемые receipts.

## Исследовательский brief с источниками

**Кто.** Аналитики, research-команды и специализированные издания.

**Задача.** Продавать вывод и методику, не отдавая полный платный материал.
Публичный summary, явные `source_refs`, Truth state и Provenance дают покупателю
основание принять решение, после чего он использует pass или per-read.

**Лучший путь.** Per-read, если конкретный brief должен оплатить его автора;
Expert Pass — для исследования коллекции.

## Библиотека устранения инцидентов

**Кто.** SRE, security responders и managed service providers.

**Задача.** Превратить проверенные remediation steps в машинно-читаемые Memory
Units. Агент ищет по симптомам, отбрасывает contested entries и покупает точный
runbook только при необходимости. Неудачная выдача освобождает резерв.

**Лучший путь.** Per-read со списком разрешённых publishers и Truth states.

## Премиальный контекст для автономных агентов

**Кто.** Операторы исследовательских, coding, procurement и support-агентов.

**Задача.** Дать агенту внешнюю экспертизу, не копируя весь corpus в prompt или
vector store. Сохраняйте listing ID, rank reasons, charge и provenance receipt
вместе с итогом агента.

**Лучший путь.** Публичный discovery и per-read authorization с лимитом затрат.

## Due diligence и compliance intelligence

**Кто.** Юристы, инвесторы, vendor-risk и compliance-команды.

**Задача.** Купить claim вместе с цепочкой evidence. Публичный listing показывает
достаточно lineage для оценки релевантности; платный доступ открывает детальный
анализ. Новые доказательства меняют Truth state и будущий рейтинг.

**Лучший путь.** Expert Pass на период активной проверки; per-read — для мнений
внешних специалистов.

## Advisory playbooks и схемы внедрения

**Кто.** Консультанты, архитекторы и специализированные агентства.

**Задача.** Упаковать не статичный PDF, а узкий decision pattern: контекст,
ограничения, failure modes, источники и следующее действие. Покупатель проверяет
provenance и сразу подаёт результат в agent workflow.

**Лучший путь.** Per-read для отдельных playbooks; pass для ограниченного по
времени клиентского проекта.

## Проверенные prompts, политики и agent handoffs

**Кто.** Разработчики агентов и AI-platform команды.

**Задача.** Продавать проверенную operating policy или handoff template вместе
с evaluation context. Provenance показывает происхождение и lineage; Truth state
отделяет tested, contested и rejected версии.

**Лучший путь.** Per-read для версионированных assets, затем локальный receipt и
явная cache policy.

## Что здесь продавать нельзя

- Wallet secrets, API keys, seed phrases и сырые credentials.
- Персональные или регулируемые данные без законной политики раскрытия и хранения.
- Unsupported claims, спрятанные за расплывчатым public summary.
- Обычные документы, которые доступны по указанному публичному источнику.
- Вечный доступ к корпусу, выданный за time-bound entitlement.

Начните с одной узкой категории, покажите достаточно evidence для решения о
покупке и следуйте [руководству по внедрению](MARKET_GUIDE.md).
