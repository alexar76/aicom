# Parcours du visiteur

Trois entrées distinctes : [présentation de la fabrique](https://modeldev.modelmarket.dev/fr/), [fabrique et catalogue](https://magic-ai-factory.com/?lang=fr), [carte de l’écosystème](https://ecosystem.modelmarket.dev/fr/).

Les deux pages de présentation expliquent la collaboration avec «Votre IA n’a pas besoin de tout savoir faire». Un exemple de tableau de bord, clairement illustratif, suit le brief, un défaut persistant, un diagnostic ciblé via AIMarket et le prochain cycle de correction et de tests d’AICOM. Le volet dépliable distingue l’achat et le rapport signé vérifiés d’une réparation complète. La fabrique opérationnelle, le catalogue et les parcours de commande sont conservés.

Première action : **Créer une landing page** → décrire une idée → examiner l’aperçu → télécharger le ZIP. La présentation et la fabrique utilisent le même générateur. `?lang=en|ru|es|fr|zh` transmet la langue choisie. La génération commence uniquement après un clic sur le bouton.

Après la génération, des liens proposent la carte et la première leçon de transaction entre agents. La fabrique propose aussi ces étapes. Le tableau public est une démo en lecture seule ; les applications complètes nécessitent votre propre déploiement. La documentation est accessible à côté de cette explication.

Le catalogue affiche tous les produits publiés par défaut, séparés en Landing pages et Produits complets, avec compteurs et liens directs. Catégories, filtre QA facultatif, recherche textuelle et technique, modèles, tags, prix et stack restent accessibles. Les échecs ou révisions actuels priment sur les résultats anciens ; QA ne garantit pas la disponibilité en production. Les descriptions gardent leur langue. Le générateur conserve les styles et l’assistant web facultatif. La page d’accueil donne accès au formulaire du pipeline, au transfert d’idées vers Admin, aux replays et aux mesures de qualité.

Les explications techniques sont repliables ; le widget du marché se charge à la demande. Les API de génération et de sous-traitance restent inchangées. Le retour arrière utilise les conteneurs et configurations nginx conservés. Un push vers Gitea ne modifie pas l’ancienne redirection GitHub Pages.
