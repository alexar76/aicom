# Visitor journey

The three entry points have distinct roles: [factory landing](https://modeldev.modelmarket.dev/), [working factory and catalog](https://magic-ai-factory.com/), [ecosystem map](https://ecosystem.modelmarket.dev/).

The two marketing landings introduce collaboration with “Your AI doesn’t have to do it all.” A shared, explicitly illustrative dashboard example follows the brief, a persistent defect, a bounded specialist diagnosis through AIMarket, and AICOM’s next repair and test cycle. Expandable evidence distinguishes the verified production purchase and signed report from a complete product repair. The working factory, catalog and ordering flows are preserved.

Start with one guest action: **Create a landing page** → describe an idea → preview → download ZIP. The homepage and marketing landing use the same generator; `?lang=en|ru|es|fr|zh` preserves the selected language. Generation is requested only when the visitor presses Generate.

After a successful generation, links lead to the ecosystem map and the first agent-transaction lesson. Factory navigation also offers these next steps. The public administration dashboard is a read-only demo; full application builds require a self-hosted factory. Documentation remains available beside that explanation.

The public catalog shows all listed products by default, in separate **Landing pages** and **Full products** sections with counts and direct links. Categories, optional QA filtering, search by text and technology, template labels, tags, prices and stack details remain available. Failed checks or a current review state override old passing evidence; QA success does not guarantee production readiness. Product descriptions retain their original language. The generator retains visual presets and its optional web assistant. The original pipeline form, idea handoff to Admin, build replays and quality metrics are accessible from the homepage.

Technical explanations are expandable; the market widget loads only when opened. Existing backend generation and procurement APIs remain unchanged. Frontend rollback uses retained containers and saved nginx configurations. GitHub publication is separate: the existing GitHub Pages redirect cannot be changed by a Gitea push.
