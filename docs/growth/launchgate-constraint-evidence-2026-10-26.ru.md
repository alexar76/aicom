# Launch Gate: факты для Stop и сохранение уведомления — 26 октября 2026

Две доработки внесены в локальный WARDEN 0.22.0 и проверены на Linux. Версия в npm не опубликована; GitHub, публичная статья и комментарии не изменялись.

## Проверка утверждений

Необязательный доверенный контракт хоста `answer_check` привязывается к точному SHA-256 ответа, сессии и ходу. Ограничения берутся из настоящего пользовательского запроса/политики, не из ответа модели и не из текста MCP-сервера. Проверяется выбранный объект и каждый объект, который ответ явно назвал допустимым. Присутствие записи в выдаче само по себе не означает допустимость.

Для четырёх прежних ошибочных списков получается конкретное расхождение: `actual 190; required <= 150`. Оно добавляется в причину перепроверки, а не заменяется общей просьбой «подумать ещё». Выбранный допустимый ID менять не требуется. Проверка не устанавливает правдивость источника: сравнение условно относительно снимка записей. Неизвестные поля не считаются пройденными; повреждённый или устаревший контракт не используется. Текст предупреждения не повторяет цитаты атаки, имена источников или произвольные названия полей.

Генератор контракта для исследования — отдельный адаптер закрытой грамматики синтетических JSON-ответов про отели. Он написан после чтения этих примеров, при исполнении не читает золотые метки. Это не универсальное извлечение условий из естественного языка и не валидация всей прозы/заявленных цен. Нативный Stop автоматически такой контракт не формирует; интеграция хоста должна передать его явно.

## Сохранение раскрытия

Из причины Stop убрана просьба повторить ответ «без упоминания этой проверки»; вместо неё — сохранить имеющееся раскрытие инструкции. Дополнительно guard записывает собственное уведомление текущего хода. После продолжения он снова выдаёт фиксированное уведомление в `systemMessage`, даже если модель удаляет предупреждение из своей прозы, без второго блокирования/продолжения. Новый пользовательский ход сбрасывает запись. Audit остаётся наблюдательным.

При том же снимке фактов в итоговом уведомлении остаются обнаруженные противоречия. Если снимок изменился или отсутствует, устранение прежних ошибок неизвестно. Сохранение уведомления в выходе hook не гарантирует сохранения текста самой модели; клиент должен показать `systemMessage`. Реальное отображение нативным клиентом в этой проверке не измерялось.
