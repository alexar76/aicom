# Jakub / KyttoMCP: проверка review на настоящем diff

Проверено 25 октября 2026 года. Это локальный отчёт; новый ответ Jakub не отправлен. Запрос автора касается выделения новых инструкций и версии пакета при review: [исходный комментарий](https://dev.to/alexar76/mcp-servers-edit-the-instructions-your-agent-reads-warden-018-shows-which-words-changed-397f#comment-3ikoh).

## Конкретный пример

Взято настоящее [изменение HISTOR № 17172](https://histor.modelmarket.dev/api/v1/changes/17172), наблюдавшееся **13 октября 2026 года в 14:12:49 UTC**: `npm:@mapled/mcp`, **33 tools → 33**. Меняются только описания `get_setup_run` и `propose_setup_plan`; состав tools и схемы прежние. Новое описание уточняет, что пользователь подтверждает план на экране Mapled, после чего агент продолжает работу. Само изменение не устанавливает атаку или обход серверной проверки approval.

Версии нужно разделять:

| Данные | До | После | Что они устанавливают |
| --- | --- | --- | --- |
| npm-артефакты, сверенные с исходным текстом | `@mapled/mcp@0.21.5` | `@mapled/mcp@0.21.6` | В каждом проверенном tarball точно найдены оба полных изменённых описания соответствующего снимка. |
| Версия из исторического MCP handshake | `0.1.0` | `0.1.0` | Только значение, сообщённое самим сервером; это не npm-версия. |
| Идентификатор в MTL descriptor | `npm:@mapled/mcp` | `npm:@mapled/mcp` | Дескриптор не содержит точной npm-версии. |

Публичная карточка сервера связывает последнее успешное наблюдение ровно с этим событием и указывает package version `0.21.6`, previousVersion `0.21.5`. Восстановление старой стороны дополнительно опирается на статическое совпадение описаний, а не на вымышленную версию из handshake. Проверены registry integrity и SHA-1 обоих npm-архивов. Архивы читались как данные, без установки и исполнения кода.

Полные [снимки, дифф и проверка артефактов](../evidence/jakub-review-2026-10-25/real-cases/README.md) сохранены локально. Все шесть tool-set digests и шесть subject digests для трёх отобранных примеров совпали с замороженным набором 20 октября. Для основного примера оба изменённых описания совпали с артефактами полностью; совпадение 29 из 33 описаний в каждой версии не подменяет проверку целого исполняемого окружения.

## Проверка опубликованного WARDEN

Проверен именно npm-релиз **WARDEN 0.21.0** в Linux-контейнере на `admin-vps`: без сети, с файловой системой read-only и временным хранилищем approval. На вход поданы настоящие сохранённые tools/list. Mapled не запускался, его handlers не вызывались, production approvals не менялись.

[Результат](../evidence/jakub-review-2026-10-25/published/result.json): **15 проверок прошли**. Review показывает два изменённых описания, удалённые и добавленные слова и отметку новой инструкции об approval у `propose_setup_plan`. После явного approval исходного снимка изменённый требует review, хотя объявленная версия сервера прежняя. Чтение статуса сохраняет первоначальное approval и не утверждает изменённые definitions автоматически. Контроль с одинаковыми снимками даёт пустой diff.

При этом найден отдельный дефект, которого эти 15 проверок не охватывали: опубликованный review предлагает npm pin **`@mapled/mcp@0.1.0`**, построенный из self-reported `serverInfo.version`. Для этого примера подтверждённый новый npm-артефакт — **0.21.6**. [Точный вывод и разбор](../evidence/jakub-review-2026-10-25/published/review-observations.json) сохранены; успешный replay не означает отсутствие этой ошибки.

## Локальное исправление

В локальном кандидате убрано построение npm pin из `serverInfo.version`; текст о неприбитом launcher уточнён с учётом npm cache. Обнаружен и исправлен второй пробел: настоящий путь `wrap` не сохранял объявленные сервером `name/version` из initialize в наблюдение и последующее approval. Теперь review получает эти метаданные и явно называет их self-reported. Они не меняют tool hash и launch identity; при отсутствии нового значения старая версия не выдаётся за текущую. Проверка CAS не позволяет подтвердить изменившееся во время review наблюдение. Исправление ещё не выпущено.

На `admin-vps`, Linux amd64 / Node 22.23.3, в Docker с runtime `runc` прошли TypeScript compilation и **142 теста в четырёх файлах**: review-diff, pin-review-origin, wrap и persistent-pins. Сборка и тесты выполнялись без сети. Загрузка зависимостей при подготовке использовала package-lock и `--ignore-scripts`; сторонние MCP-пакеты не исполнялись.

Отдельный replay настоящего diff через окончательный локальный build прошёл **19 из 19 проверок**. Он сохраняет подсветку approval и прежний pin, но больше не предлагает `@mapled/mcp@0.1.0` и не утверждает, что каждый `npx` обязательно загрузит latest. [Результат и вывод](../evidence/jakub-review-2026-10-25/candidate/result.json), [review](../evidence/jakub-review-2026-10-25/candidate/rpc-review.txt), [лог тестов](../evidence/jakub-review-2026-10-25/candidate-final-tests.log) сохранены.

Первый минимальный тестовый перенос не включал repository test setup и собственный example; из-за этого три существующие проверки не прошли. Также исправлена ошибка Python-помощника нового race-теста: прежняя проверка любого исключения могла принять ошибку помощника за ожидаемый отказ. Окончательный тест требует именно отказ CAS. Первые неудачные логи сохранены отдельно; окончательный перенос и скомпилированные файлы зафиксированы SHA-256. Optional serverInfo отбрасывает непарные UTF-16 суррогаты, чтобы они не ломали вычисление RFC 8785 pin revision.

Название версии в локальном package.json всё ещё `0.21.0`; это **не** делает локальный build опубликованным npm-артефактом 0.21.0. Исходники, команды и результаты различаются в [индексе доказательств](../evidence/jakub-review-2026-10-25/README.md). Исходники и результаты сверены перед удалением нашего временного каталога; production не менялся.

Это проверка воспроизводимого вывода review и поведения approval. Удобство для человека и сам KyttoMCP здесь не измерялись; новый запуск Mapled из npm не выполнялся. Для будущего отдельного запуска точная запрошенная версия задаётся через `npm exec --yes --package=@mapled/mcp@0.21.6 -- mapled-mcp`; ему нужен `MAPLED_MCP_TOKEN`. Само указание версии ещё не удостоверяет установленные байты артефакта. Такая команда в рамках этой проверки не исполнялась.
