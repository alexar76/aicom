# Проверка корзины через n8n и собственный хаб

[English](n8n-workshop.md) · [Русский](n8n-workshop.ru.md) · [Español](n8n-workshop.es.md) · [Français](n8n-workshop.fr.md) · [中文](n8n-workshop.zh.md)

Практический онлайн-семинар на 60 минут для n8n-интеграторов и владельцев небольших API.
Создаём сервис, который отвечает: **«Может ли поставщик собрать эту корзину и какова
стоимость товаров?»** Workflow и каталог остаются под контролем владельца. Для упражнения
не нужны покупка, кошелёк, платная LLM или внешний клиент.

## Зачем этот сценарий

Помощник магазина, агент продаж или закупочный агент обращаются к одному сервису с правилами
поставщика. n8n выполняет эти правила, Hub публикует описание услуги и проверяет подпись ответа.
У n8n уже есть [собственный MCP](https://n8n.io/mcp/): для доступа своего агента к своему
workflow его может быть достаточно. Здесь изучаем дополнительный слой: независимый каталог
услуг, подписи поставщика и возможность дальнейшего подключения к федерации.

Учебные товары и остатки **синтетические**. Пример показывает интеграцию, а не реальные
складские данные, спрос или промышленное развёртывание. Hub бесплатен; инфраструктуру
обеспечивает владелец, у n8n своя лицензия. Федерация — потенциальный канал распространения.

## Пример и ожидаемые результаты

[Workflow для импорта](../examples/n8n-order-check/workflow.json) ·
[Код и подробности запуска](../examples/n8n-order-check/README.md) ·
[Протокол проверки](../examples/n8n-order-check/VALIDATION.md)

```json
{"items":[{"sku":"BEANS-250","quantity":2},{"sku":"MUG-BLUE","quantity":1}]}
```

Ожидаем `status: ready`, `can_fulfill: true`, `subtotal_minor: 3430`, `currency: USD`.
Это 34,30 USD за товары. Налоги, доставка и итог к оплате — `null`, то есть не рассчитаны.
Ответ содержит `demo: true`, `reservation_created: false`, `order_created: false`.

| Запрос | Результат |
|---|---|
| Две BEANS-250 и одна MUG-BLUE | Доступны; стоимость товаров 3430 |
| Четыре MUG-BLUE | Недостаточно: доступны три |
| Неизвестный SKU | Неизвестный товар; стоимость корзины не рассчитана |
| Две строки по две MUG-BLUE | Складываем в четыре; недостаточно |
| Пустая корзина, отрицательное или дробное количество | Отклоняем ввод |
| Неверный ключ webhook / недоступный n8n | Отказ / ошибка; расчёт не выдумываем |

`evaluated_at` — время выполнения, а не свежесть остатков. Подпись подтверждает источник
заявления и связь с запросом; она не доказывает наличие товара на складе.

## Подготовка до встречи

Нужны отдельный локальный экземпляр, Python 3.11+, Node.js 24.14.0 и свободные порты
15678/13456/19083. Из корня клона этого репозитория:

```bash
python3 -m venv examples/n8n-order-check/.venv
examples/n8n-order-check/.venv/bin/python -m pip install -e './aimarket-hub[pqc]'
cd examples/n8n-order-check
source .venv/bin/activate
npm install --prefix .runtime/npm n8n@2.43.7 --no-audit --no-fund
export PATH="$PWD/.runtime/npm/node_modules/.bin:$PATH"
python run.py init
python run.py n8n-import
```

Установка не входит в 60 минут. Секреты и ключи создаются в `.runtime/`, исключённом из Git;
не передавайте этот каталог другим. В workflow нет встроенного токена: используется Header
Auth credential. Повторный импорт выполняйте при остановленном учебном n8n.

В трёх терминалах перейдите в каталог примера, активируйте `.venv` и запустите соответственно:
`python run.py n8n`, `python run.py adapter`, `python run.py hub`. В терминале n8n повторите
экспорт PATH. Редактор: `http://127.0.0.1:15678`; при запросе создайте локальную учётную запись
владельца. Импорт публикует workflow; адаптер использует `/webhook/`. Ctrl+C останавливает
серверы; локальные данные сохраняются.

## План на 60 минут

| Минуты | Действие |
|---|---|
| 0–5 | Кто владелец, кто вызывает, что получаем; обозначаем тестовые данные |
| 5–15 | Webhook → Code → Respond to Webhook; прямой вызов с аутентификацией |
| 15–25 | Схема ввода, повторяющиеся SKU, правила остатков и расчёта |
| 25–40 | Адаптер и Hub; вызов услуги, разбор результата и подписей |
| 40–50 | Недостаток товара, неизвестный SKU, неверное количество и ключ |
| 50–60 | Как подключить один разрешённый источник владельца; вопросы |

Перед проверками дождитесь сообщения n8n о готовности редактора и завершении индексации workflow.

```bash
curl --fail-with-body http://127.0.0.1:19083/ai-market/v2/invoke \
  -H 'Content-Type: application/json' --data-binary @request.json
python run.py check
node test_quote.cjs
```

Для локального MCP-клиента: `http://127.0.0.1:19083/mcp`. Пример задания:
«Найди учебную проверку корзины. Проверь две BEANS-250 и одну MUG-BLUE. Покажи стоимость
товаров и нехватку, укажи, что данные синтетические. Не оформляй заказ».
Облачный клиент не имеет доступа к loopback ноутбука. Проверка протокола HTTP/MCP не
подтверждает работу в каждом пользовательском приложении агента.

## Первый настоящий оператор

Нужны обезличенный пример ответа каталога и разрешение владельца источника. Вместо фикстуры
подключаем чтение: валюта, цены в минимальных денежных единицах, доступный остаток и время
наблюдения источника. Задаём допустимый возраст данных. Одновременно обновляем учебный
контракт ответа адаптера и тесты. Резервирование и оформление заказа — отдельные операции.
Для закрытых или индивидуальных цен нужны авторизация вызывающего и изоляция клиентов.

Для публичного запуска: постоянные ключи и БД Hub, HTTPS и ограничения запросов;
n8n/адаптер — в закрытой сети с аутентификацией. Учебные HTTP-настройки не переносим.
Далее [руководство оператора](https://github.com/alexar76/aimarket-hub/blob/main/docs/operator-quickstart.ru.md),
`aimarket doctor` и, по выбору владельца, announce. Локальный успех не означает допуск в федерацию.

Критерий результата: независимый владелец управляет установкой и ключами, повторяет полезный
вызов и умеет остановить сервис. Отдельно учитываем локальный запуск, реальные данные,
допуск в федерацию и использование через семь дней. Продажа внешнему покупателю не обязательна.
