# Запустите собственный хаб датчиков бесплатно

[English](sensor-operator.md) · [Русский](sensor-operator.ru.md) · [Español](sensor-operator.es.md) · [Français](sensor-operator.fr.md) · [中文](sensor-operator.zh.md)

**Разверните и используйте Hub + GAIA бесплатно на своей инфраструктуре**, сохраняя контроль над ключами, данными датчиков и сервисами. Руководство предназначено для владельцев станций, локальных сообществ датчиков и небольших IoT-интеграторов. Инфраструктуру предоставляете вы; за самостоятельное использование ПО нам не нужно платить лицензионный или абонентский сбор.

После обычного допуска федерация AIMarket — потенциальный рынок сбыта ваших предложений. Продавать доступ необязательно; цены определяете вы, покупатели и доход не гарантированы. Пример платного сервиса ниже описывает эту дополнительную возможность. Для начала использования собственного хаба не нужно покупать данные или совершать продажу.

Хороший первый сервис — фактическое измерение в месте, где покупателю доступен лишь прогноз или мало наблюдений. Опишите расположение, измеряемые величины, частоту обновления и ограничения датчика. Для копии общедоступного источника потребуется отдельное объяснение её пользы.

Это инструкция по подключению, а не отчёт об уже проведённом запуске оборудования и не обещание дохода. После допуска федерация помогает обнаружить ваш сервис; решение о покупке остаётся за потребителем.

## Что вы запускаете

Путь данных: **ваш датчик → ваш адаптер → GAIA → ваш Hub → покупатель**. GAIA принимает показания и подписывает результат; Hub публикует услугу, обрабатывает настроенный способ оплаты и возвращает квитанцию. Подпись подтверждает происхождение и целостность данных, но сама по себе не доказывает точность измерения.

Готовый API-бизнес не требуется. Нужен способ преобразовывать показания вашего устройства в JSON ниже. Приём данных не означает автоматическую совместимость с любым устройством Tasmota, ESPHome, Home Assistant, TTN или SenML: преобразование формата конкретного оборудования выполняет адаптер.

Текущий универсальный приёмник принимает `temperature_c`, `humidity_pct`, `pressure_hpa`, `pm2_5_ugm3`, а также обязательные `latitude` и `longitude`. Передавайте только действительно измеряемые поля. Идентификатор — `feeder-iot-01`, продаваемая возможность — `gaia.iot.read@v1`. Сейчас один экземпляр предоставляет один универсальный IoT-приёмник. Для нескольких станций нужны отдельные экземпляры или явное расширение реализации, а не произвольные новые идентификаторы.

## 1. Запустите закрытый сервис GAIA

Нужны Docker, `curl`, `jq`, адаптер, экспортирующий настоящие измерения, и инициализированный Hub по [руководству оператора](https://github.com/alexar76/aimarket-hub/blob/main/docs/operator-quickstart.ru.md). В примере GAIA работает в Docker, а Hub — непосредственно на **той же машине**. Собирайте образ из корня AICOM на проверенной вами ревизии:

```bash
docker build -f gaia/Dockerfile -t local/gaia-sensor .
export GAIA_FEEDER_TOKEN="$(openssl rand -hex 32)"
docker run -d --name gaia-sensor \
  -p 127.0.0.1:9320:9320 \
  -v gaia-sensor-data:/data \
  -e GAIA_FEEDER_TOKEN \
  -e GAIA_ENABLE_LIVE=1 -e GAIA_FEEDER_ENABLED=1 \
  -e GAIA_SIM_CONTROL=0 -e AIFACTORY_PROD=1 \
  -e GAIA_PUBLIC_URL=http://127.0.0.1:9320 \
  -e GAIA_KEY_DIR=/data/devices \
  -e GAIA_SIGNING_KEY_PATH=/data/gaia_signing_key \
  local/gaia-sensor
```

Сохраните сгенерированный токен приёма в закрытой конфигурации; клиент загрузки использует то же значение. Сохраняйте том `/data` с ключами шлюза и устройств. GAIA в примере доступна только через loopback: покупатели обращаются к Hub. Для удалённого датчика нужен защищённый HTTPS-канал или частная сеть до приёмника, а не открытый порт сервиса поставщика.

В текущем запуске нужны обе настройки: `GAIA_ENABLE_LIVE=1` и `GAIA_FEEDER_ENABLED=1`. GAIA также регистрирует встроенные ретрансляторы и симуляторы; здесь на Hub публикуется только ваша услуга `gaia.iot.read@v1`. Не представляйте симулированные станции как собственное оборудование.

## 2. Передайте настоящее измерение

Адаптер должен записать `station-reading.json` следующего вида. До отправки замените все текстовые заполнители настоящими **числами JSON**: шаблон не является измерением. `observed_at` — время наблюдения датчика в Unix-секундах, а не время повторной отправки старого показания.

```json
{
  "device_id": "feeder-iot-01",
  "observed_at": "<observed_at>",
  "fields": {
    "latitude": "<latitude>",
    "longitude": "<longitude>",
    "temperature_c": "<temperature_c>"
  }
}
```

Отправьте данные, затем прочитайте то же устройство локально:

```bash
curl --fail-with-body -sS http://127.0.0.1:9320/feeder/v1/ingest \
  -H "Authorization: Bearer $GAIA_FEEDER_TOKEN" \
  -H 'Content-Type: application/json' \
  --data-binary @station-reading.json

curl --fail-with-body -sS http://127.0.0.1:9320/ai-market/v2/invoke \
  -H 'Content-Type: application/json' \
  -d '{"product_id":"gaia.gateway","capability_id":"gaia.iot.read@v1","input":{"device_id":"feeder-iot-01"}}'
```

Приём должен вернуть `ok: true`, а вызов — результат с показанием и аттестацией. Проверьте устройство, значения и источник в ответе. Проверяйте и JSON: при недоступном показании возможен `ok: false` даже с HTTP 200. Этот локальный вызов поставщика проверяет связь и не является продажей.

Передавайте обновления чаще текущего предела свежести в 600 секунд. Без показаний или при их устаревании источник недоступен. Сейчас сохраняется только последнее наблюдение **в памяти процесса**: после перезапуска перед приёмом покупок нужно отправить новое показание. Постоянное хранение ключей не превращает приёмник в архив измерений.

## 3. Опубликуйте показания на своём Hub

В рабочем каталоге и окружении инициализированного Hub задайте в `SENSOR_PAY_TO` **адрес своего кошелька для приёма оплаты**, никогда не закрытый ключ. В примере цена — $0.002 за вызов; установите свою. Получите открытый ключ шлюза GAIA локально и закрепите его в записи каталога:

```bash
: "${SENSOR_PAY_TO:?Set SENSOR_PAY_TO to your receiving wallet address}"
GAIA_PROVIDER_KEY="$(curl -fsS http://127.0.0.1:9320/.well-known/ai-market.json | jq -er .signer_public_key)"
export AIMARKET_INVOKE_HOST_GATEWAY=127.0.0.1
aimarket add gaia.iot.read@v1 \
  --product gaia.gateway \
  --url http://127.0.0.1:9320/ai-market/v2/invoke \
  --provider-pubkey "$GAIA_PROVIDER_KEY" \
  --price 0.002 --pay-to "$SENSOR_PAY_TO" \
  --name "Local station readings" \
  --description "Current measurements from the operator's own station" \
  --input-schema '{"type":"object","properties":{"device_id":{"type":"string","enum":["feeder-iot-01"]}},"required":["device_id"],"additionalProperties":false}'
```

Запустите или перезапустите `aimarket serve` с той же базой Hub и `AIMARKET_INVOKE_HOST_GATEWAY=127.0.0.1` в окружении сервиса. Это явно разрешает Hub вызывать своего локального поставщика. Для Hub в контейнере или на другом сервере используйте схему сети из [руководства production-развёртывания](https://github.com/alexar76/aimarket-hub/blob/main/docs/production-deployment.md): loopback контейнера относится к самому контейнеру.

GAIA уже подписывает ответы поставщика; `--provider-pubkey` позволяет Hub проверять их. Локальная команда `aimarket add` публикует вашу собственную услугу. Публикация на чужом Hub проходит отдельный путь допуска.

## 4. Проверьте требование оплаты

Обратитесь к Hub без оплаты и без заголовка песочницы:

```bash
curl -sS -i http://127.0.0.1:9083/ai-market/v2/invoke \
  -H 'Content-Type: application/json' \
  -d '{"product_id":"gaia.gateway","capability_id":"gaia.iot.read@v1","source_hub":"local","input":{"device_id":"feeder-iot-01"}}'
```

Для платной услуги с настроенной оплатой ожидается `402` с платёжным предложением. До покупки проверьте сумму, сеть, актив и получателя. Если без оплаты выданы показания, проверка платёжного ограничения не пройдена.

`--pay-to` задаёт получателя; перед публичным запуском завершите настройку прямой оплаты продавцу по [руководству оператора](https://github.com/alexar76/aimarket-hub/blob/main/docs/operator-quickstart.ru.md). Настоящий покупатель следует предложению, авторизует оплату и повторяет вызов через поддерживаемый клиент. Сохраните квитанцию и проверьте поступление средств. Созданный для теста локальный кредитный баланс не является внешней выручкой.

Пример не включает Pay-on-Verified. Подписанные показания сами по себе не означают расчёт по результату проверки или автоматический возврат уже выполненного прямого платежа. Доход после расходов зависит от реальных платных вызовов, комиссий, хостинга и обслуживания датчика; членство в федерации не гарантирует продажи.

## 5. Вступите в федерацию по обычным правилам

Разверните Hub на публичном HTTPS по production-руководству, оставьте GAIA закрытой и замените `hub.example.com` своим адресом. Сохраните бесплатную подписанную `hub.ping@v1`, созданную quickstart, для проверки допуска. При переносе в production сохраните прежние ключи и базу.

```bash
aimarket quickstart --url https://hub.example.com --no-buyer
aimarket doctor --url https://hub.example.com
curl --fail-with-body -sS https://modelmarket.dev/ai-market/v2/federation/announce \
  -H 'Content-Type: application/json' \
  -d '{"hub_url":"https://hub.example.com","hub_name":"My sensor hub"}'
```

Проверьте вердикт по возвращённому `assay_url`. Видимость в мониторе и объявление со статусом pending **не** дают допуск, индексацию или маршрутизацию. Неуспешную проверку нужно исправить по действующим правилам. Подробнее: [вступление в федерацию](join-the-federation.ru.md). Покупатель должен передавать в вызов `source_hub`, полученный из поиска.

Точка датчика на ATLAS добавляется отдельно от допуска Hub. Автоматическое появление на карте не обещается: используйте [руководство GAIA → ATLAS](i18n/add-gaia-atlas-sensor.ru.md) для поддерживаемого типа или проверенную новую интеграцию.

## Подключите свою станцию

Чтобы обсудить первое подключение, создайте тему в [GitHub Discussions](https://github.com/alexar76/aicom/discussions). Укажите модель устройства, доступные поля, примерную территорию измерений, частоту наблюдений и обновлений, формат экспорта и возможность запустить Hub. Не публикуйте токены и закрытые ключи.

Первый полезный результат — свежее показание вашего устройства, купленное внешним клиентом, с квитанцией и подтверждённой оплатой. Затем оценивайте повторные покупки и продолжение работы. Тестовые покупки отмечайте отдельно. Оператор сообщества может объединить нескольких владельцев, но для каждой независимой станции нужно расширить текущую реализацию с одним приёмником или развернуть отдельный экземпляр.
