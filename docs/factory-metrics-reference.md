# Factory Metrics Reference

This document is the canonical metric inventory for AI-Factory operations.

## 1) Pipeline Metrics

- `pipeline_products_total{state}`: number of products per state.
- `pipeline_active_products`: non-terminal products in flight.
- `pipeline_products_created_total`: cumulative products created.
- `pipeline_tasks_total{status}`: cumulative tasks by status.
- `pipeline_task_duration_seconds{agent_type}`: task runtime histogram.
- `pipeline_metrics.completion_rate`: completed / total products (%).
- `pipeline_metrics.pending_tasks`, `running_tasks`, `timeout_tasks`.
- `pipeline_metrics.avg_completion_time_hours`: average idea-to-terminal cycle (hours).
- `pipeline_metrics.mean_time_to_remediation_hours`: mean DEV_FIXING cycle time.
- `pipeline_metrics.benchmark_pass_rate`: latest benchmark pass-rate.
- `pipeline_metrics.benchmark_regression`: latest drop vs previous benchmark snapshot.

## 2) Director Metrics

- `director_decisions_total{action,type}`: decisions generated by action/type.
- `director_analysis_duration_seconds`: analysis cycle duration histogram.
- Director state file metrics:
  - pending decisions,
  - applied decisions.

## 3) LLM Metrics

- `llm_requests_total{provider,status}`: request volume and error mix.
- `llm_request_duration_seconds{provider}`: latency distribution.
- `llm_provider_health{provider}`: provider health gauge (1/0).
- `llm_circuit_state{provider}`: circuit breaker state (**0** = closed, **1** = half_open, **2** = open).
- `llm_circuit_failures_total{provider}`: failures recorded by the breaker.
- `llm_circuit_opens_total{provider}`: times the circuit opened.
- `llm_circuit_recovery_duration_seconds{provider}`: histogram from OPEN to successful recovery.

Admin UI and SSE/WebSocket metrics include a **`circuit_breakers`** object (per-provider state, failure window, recovery time). See **[admin-guide.md](./admin-guide.md#llm-providers)**.

## 4) Quality & Release Metrics

- `quality_constitution.passed`: hard release contract pass/fail.
- `quality_constitution.checks.*`:
  - domain_e2e,
  - acceptance_traceability,
  - maintainability,
  - ux,
  - security,
  - observability,
  - perf,
  - perf_slo,
  - traceability_matrix,
  - implementation_plan,
  - lifecycle_release,
  - runtime_e2e.
- `release_cockpit.go_no_go`: `go` / `no-go`.
- `release_cockpit.checks.*`:
  - quality_constitution,
  - lifecycle_artifact,
  - release_protocol_executed,
  - benchmark_passrate,
  - perf_regression.
- `release_cockpit.details.perf_regression`:
  - samples,
  - recent_p95_ms_avg,
  - baseline_p95_ms_avg,
  - ratio,
  - max_ratio.

## 5) Marketplace Listing Metrics

- `marketplace_verified`: listing eligibility on storefront.
- `quality_score`, `quality_grade`, `spec_coverage_pct`.
- `telemetry_qa_gates_passed`.
- `release_score`.
- Marketplace constraints are policy-driven:
  - always: demo quality gates (`assess_product_demo` / `quality_gates_pass`);
  - optional toggles: full QA telemetry, design novelty threshold, QA realism findings, release score threshold;
  - optional stricter toggles: quality constitution, release cockpit, non-placeholder product name.

## 6) Benchmark Metrics

- `benchmark_scorecard.runs_total`, `runs_last_24h`, `runs_last_7d`.
- `benchmark_scorecard.pass_rate_last_24h_avg`.
- `benchmark_scorecard.pass_rate_last_7d_avg`.
- `benchmark_scorecard.latest.pass_rate`.
- `benchmark_scorecard.status`:
  - `ok` (reports available),
  - `no_reports` (missing benchmark data).
- `benchmark_alerts.alerts[]`:
  - degradation alerts,
  - missing-data alerts.

## 7) Feedback & Telemetry Metrics

- Feedback volume:
  - `feedback_items_total`,
  - per-product feedback counts.
- Quality of feedback:
  - `avg_rating`,
  - bug report count,
  - negative journey vote count (`journey_prompt` + `no`).
- Session/telemetry summaries:
  - event counts,
  - replay session counts,
  - timeline size.

## 8) Finance & Crypto Metrics

- Revenue by product (windowed):
  - order count,
  - gross revenue.
- Revenue split:
  - fiat revenue,
  - crypto revenue.
- Revenue by chain:
  - top chains by volume,
  - share fiat vs crypto.
- Weekly governance KPIs:
  - `revenue_7d`, `revenue_prev_7d`,
  - growth rate 7d vs prior 7d,
  - `defects_7d`, `defects_prev_7d`.
- Crypto strategy KPIs:
  - chain concentration,
  - chain-level margin estimate (if costs are available).

## 9) Inspector Metrics

Independent inspector report (generated each cycle):

- `summary.products_total`
- `summary.problematic_products`
- `summary.benchmark_status`
- `summary.benchmark_alerts_count`
- Per product:
  - state,
  - feedback quality,
  - order/revenue snapshot,
  - risk flags.
- `crypto_summary`:
  - fiat_revenue,
  - crypto_revenue,
  - top_chains,
  - fiat_vs_crypto_share.
- `recommendations[]`:
  - hardening_batch,
  - benchmark_required,
  - benchmark_alerts_present,
  - crypto focus recommendations.

## 10) Metrics-to-Action Mapping

- Low completion rate -> Director decision: throughput/quality intervention.
- Pipeline SLO breach (pass-rate / regression / MTTR) -> non-approval auto-action:
  - `trigger_benchmark_and_rework_cycle`,
  - mandatory benchmark rerun + remediation queue.
- High timeout or repeated failure -> inspect agent stage and queue strategy.
- `no_reports` benchmark status -> force benchmark run before release.
- Inspector problematic products -> run catalog hardening/remediation.
- Crypto revenue concentration -> prioritize best-performing chain in market defaults.
