# x402 交付调查——向 100 个卖家各发起一次付费调用

> 🌐 [English](x402-delivery-survey.md) · [Русский](x402-delivery-survey.ru.md) · [Español](x402-delivery-survey.es.md) · [Français](x402-delivery-survey.fr.md) · **中文**

**二十多个信任索引在检查 x402 卖家是否会报价。我们检查的是买家付款之后实际拿到了什么。**

2026 年 10 月 5 日，我们从 CDP Bazaar 中随机抽取了 100 个卖家。我们向每个卖家发送其自己列表中的示例请求，用 Base 上的 USDC 付费，并在链上核对扣款。随后由五个模型组成的陪审团评判每一个回答。本文不点名任何卖家，原因见[为什么不公布名称](#为什么不公布名称)。

## 结果

| 结果 | 卖家数 |
|---|---|
| 回答被陪审团接受 | 74 |
| 回答被陪审团拒绝，买家已被扣款 | 3 |
| 收到回答，陪审团在两个方向上都未达到足够置信度 | 8 |
| 付款后出错，买家**未**被扣款 | 9 |
| 付款后出错，买家已被扣款 | 1 |
| 未购买 | 5 |
| **合计** | **100** |

- **购买。** 共签署 95 笔付款，总计 $0.536。链上执行 85 笔，共 $0.489。
- **被接受的回答。** 85 次付费调用中有 74 次（87%）返回了列表所承诺类型的真实回答。
- **付了钱却一无所获。** 85 次付费调用中有 4 次（4.7%）扣了买家的钱却没有给出有用的回答，合计 $0.022。
- **诚实的失败。** 九个卖家在付款后出错，没有收钱；其中几家在错误信息里直接写明（“you were not charged”）。
- **响应时间。** 付费调用的响应时间中位数为 1.9 秒，第 90 百分位为 4.3 秒，最长 40 秒。

## 出了什么问题

| 问题 | 卖家数 |
|---|---|
| 列表自己的示例无法使用：服务拒绝它，或导致错误，或回显字段说明 | 7 |
| 列表自己的示例无法发送：用占位符代替取值，或使用 HTTP 客户端不会发送的请求体类型 | 2 |
| 付款后上游故障（网关 502、RPC 宕机、模型冷启动、价格数据源重连） | 4 |
| 扣款之后出错 | 1 |
| 收钱却返回空结果 | 1 |
| 收钱却返回不完整结果（“partial”“indeterminate”） | 1 |
| 本应是承诺数据的地方变成了错误报告 | 1 |
| 结算响应头写着“已付款”，链上却没有转账 | 1 |
| 已扣款，但没有发送结算响应头 | 1 |
| 402 混用了 x402 v1 和 v2 字段，参考客户端拒绝付款 | 1 |
| 402 中的收款方与列表中的收款方不一致 | 1 |
| 实际价格高于列表价格 | 1 |
| 未付费请求在 20 秒内没有回应 | 1 |

一个卖家可能有不止一个问题。

几乎没有可以称为欺诈的情况。最常见的缺陷是列表本身：大约每十个卖家中就有一个展示了无法使用的示例请求。照着文档调用的买家代理会得到一个错误。通常不会因此被扣款，但也拿不到回答。

## 402 探测看不到什么

我们找到的每个索引都只发送一个未付费请求并读取 402。在我们的样本中，100 个卖家里有 96 个通过了这项测试。有几件事只有在付款时才会显现：

- 文档中的示例是否可用；
- 卖家是否在出错时照样扣款；
- 它报告的结算是否真的上了链；
- 一个 200 响应究竟是真正的回答还是空列表。

本调查的数字来自 95 次付费调用，而不是 402。

## 更大的发现：需求

Bazaar 公布了它自己的 30 天计数。在 34,768 个列表中，有 22,559 个（65%）在 30 天内恰好只有一个付款钱包，很可能是卖家自己为了被收录而付了一次。只有 396 个（1.1%）有十个或更多付款方。在我们的样本中，74 个回答被接受的卖家里有 23 个恰好只有一个付款方。

x402 市场看起来并不缺信任，缺的是买家。

## 方法

- **目录。** 2026-10-05 19:47 UTC 的 CDP Bazaar 发现 API：34,768 个列表。快照已保存，sha256 为 `6de6966927e5cc5b83f55f7c128c48861eab4cebf1e3fb61c2c9cb0d583d876c`。
- **符合条件的列表。** x402 v2、HTTPS、声明了示例请求（`extensions.bazaar.info.input`），并且有 Base 主网上不超过 $0.01 的 USDC `exact` 报价。我们自己的主机和钱包、以及兄弟生态的主机和钱包都已排除。剩下 1,466 个主机上的 28,382 个列表。一个主机算作一个卖家。
- **样本。** 用种子 `aimarket delivery survey 2026-10-05` 与主机名的 sha256 抽取 100 个主机。每个主机用同样的方法抽取一个列表。任何持有快照和种子的人都会抽到同样的卖家。
- **请求。** 完全使用卖家声明的示例：方法、路径参数、查询参数和请求体。声明的请求头没有发送，它们大多是卖家自己的 API 密钥。
- **空跑。** 同一个请求不付款发送，读取 402 并与列表比对。有 96 个卖家可以在上限内、向列表中的收款方付款。
- **购买。**
  - 重新读取 402，只有当其条件与空跑时逐字一致才付款。
  - 买方是 x402 参考客户端 2.28，其自身的支出上限设为 $0.01。它只能签署 EIP-3009 的 `transferWithAuthorization`：从不签 Permit2，从不签授权额度。
  - 整次运行设有 $0.55 的硬性预算。每个回答都作为证据保存。
- **扣款。** 对每一笔已签署的付款查询 Base 上 USDC 合约的 `authorizationState(payer, nonce)`。这是链上的记录，而不是卖家的说法。
- **评判。**
  - 陪审团是 Metis：来自五家厂商的五个模型。它的提示词和判决读取方式，正是在 [Pay-on-Verified](pay-on-verified-demo.zh.md) 中释放托管资金的那一套；另见 [jury-3-vs-5.zh.md](jury-3-vs-5.zh.md)。
  - 问题是：这个回答是否是对该请求的真实、完整的回应，且属于列表所承诺的类型——而不是错误、空的或占位的结果、要求追加付款或凭证、或无关内容？
  - 只有当陪审团自身的置信度至少为 0.7 时，判决才算数。
  - 我们人工抽查了 12 个被接受的回答，全部是真实的：一个 768 维的嵌入向量、一篇维基百科文章、Product Hunt 数据、一个正确的 Web Mercator 反投影。

## 局限

- **一个时刻，一次调用。** 每个卖家只在某一天收到一次调用。在那一分钟宕机的卖家就记为宕机。
- **只用卖家自己的示例。** 简单的示例（“解析 user agent `example`”）得到简单的回答，而这样的回答会通过。
- **不是事实核查。** 陪审团判断回答是否真实、是否属于承诺的类型。在能核对事实的地方（投影、文章）它核对了；一般情况下不核对。
- **只是市场的一小部分。** 价格不超过 $0.01、在 Base 上、声明了示例的卖家。更贵的列表或没有示例的列表不在覆盖范围内。
- **我们与结论的利害关系。** 我们运营 [AIMarket](https://modelmarket.dev)——一个代理向代理付费的市场——并且出售验证服务。正因如此，种子、工具和匿名化数据都是公开的；也正因如此，本报告如实说出它的发现：大多数卖家都会交付。

## 为什么不公布名称

某一天的一次付费调用，对一家企业而言只是很薄的证据，而且我们的请求未必是卖家设想的用法。我们没有公布名单，而是这样处理：

- **数据。** 每个卖家的匿名化记录在 [`scripts/delivery-survey/results/2026-10-05.json`](../scripts/delivery-survey/results/2026-10-05.json) 中。各记录在每种结果内部被打乱，价格和付款方数量以区间给出，不含主机名和交易。
- **非公开证据。** 完整文件——主机、请求、回答、交易和判决——的 sha256 为 `f55c952d752319d1a862c7154f8d93ca0aa675b5cd1172b368846e5fbe2f5cf9`，因此发布后无法更改。每个卖家都可以看到自己的那一行。
- **联系卖家。** 我们正在逐一联系列表存在问题的卖家，每个卖家都附上其自己的证据。

卖家也可以用同一个工具自查。不付费的那一步不花钱：

```bash
cd scripts/delivery-survey && npm ci
node survey.mjs catalog --out bazaar.json
node survey.mjs sample --catalog bazaar.json --host your.host --cap 0.01 --seed self --out plan.json
node survey.mjs probe --plan plan.json --out probe.jsonl      # 不付费：你自己的示例和你的 402
node survey.mjs buy --plan plan.json --probe probe.jsonl --out buy.jsonl --budget 0.05 \
  --payer 0xYourBuyer --key-file wallet.json                   # 每个列表一次付费调用
node survey.mjs chain --buy buy.jsonl --out chain.json         # 是否被扣款，以链上为准
```

`wallet.json` 中存放一个一次性买家钱包的 `{"mnemonic": "…"}`（`--address-index` 选择账户）。请使用只放了几美分的独立钱包。
