HISTOR от 20 октября, а не новый опрос серверов. Запуск — на admin-vps в Linux,
без сети внутри контейнера, с read-only входными данными. MCP-серверы и сторонние
пакеты не запускаются; используются Python stdlib и установленный собственный

## Классификация

Основные корзины событий взаимоисключающие, приоритет сверху вниз:

1. composition: добавление/удаление имени tool (переименование = remove + add).
2. schema_contract: структурное изменение схемы, ограничений, defaults, $schema,
   $id, $ref или неизвестного ключа. Это консервативная группа, а не доказательство
   несовместимости. Порядок type/oneOf/etc автоматически не нормализуется.
3. description_text: изменение текста описания сверх цифр и whitespace.
4. description_numeric: после удаления whitespace совпадают все нечисловые
   фрагменты, меняются только существующие последовательности десятичных цифр.
5. schema_order: только точная перестановка уникальных элементов required/enum
   при отсутствии более приоритетных изменений.
6. schema_annotation: title/examples/$comment в действительном узле схемы.
7. description_whitespace: после удаления Unicode whitespace строки равны.
8. unchanged: нет различий измеряемых четырёх полей.
9. unknown: хотя бы одно полное состояние недоступно.

Независимые флаги сохраняют пересечения: состав tools, верхнее описание tool,
description внутри схемы, inputSchema, outputSchema, контракт, порядок, прочие
аннотации. Новые/удалённые tools и новые/удалённые узлы схем учитываются в составе/
контракте; их вложенные описания не считаются редактурами существующего описания.

Description распознаётся только в действительных узлах JSON Schema. Поле с именем
description внутри properties — имя параметра, внутри default/enum/examples —
буквальные данные. Корневое описание схемы входит в description внутри схемы.
Булевы значения и числа сравниваются с учётом типа. JSON object/tool order уже
устраняется исходным digest; повторно считать такое форматирование нельзя.

Whitespace-only, numeric-only, order-only и annotation-only — механические
признаки. Ни один из них не означает «безопасная косметика»: числовой лимит,
пример, пробел внутри инструкции или schema dialect могут менять поведение.
Маска не изменяет trust digest и не является предлагаемым bypass проверки.

## Проверки

- До подсчёта: независимые unit tests на длинные описания, смешанные изменения,
  схемы/буквальные данные, отсутствующую outputSchema, bool/int, перестановки.
- Сверить raw-флаги с summary; расхождения сохранить, не замалчивать.
- Воспроизвести старую diff-ops эвристику 2 719 numeric events и шесть whitespace
  events отдельно. Она охватывала другую выборку и не тождественна новой маске.
- После подсчёта: независимый пересчёт JSONL, суммы корзин/пересечений, SHA-256,
  неизвестные состояния и цепочки соседних непустых digest.
- Сохранить сценарии, тесты, логи, hashes, результаты и примеры. Ничего не
  публиковать и не отправлять Arhan в рамках данного поручения.
