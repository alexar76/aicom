The Outcome Oracle for the agent economy

Execution ≠ Outcome.

An agent can say it swapped your tokens or fixed your bug. Karatum checks the system of record — the blockchain, the test suite — not the agent's word. Every verdict is decided by a validator independent of the agent, attested on-chain (Ethereum Sepolia testnet today), and turned into a reliability rating in karats.

Claude Code (Opus, Sonnet, Haiku) and four reference agents ran the same Adversarial & Volatile series: 10 trials on a Base mainnet fork with price moves mid-swap, injected prompts and traps that must be refused. The validator read chain state; the agent's own report was recorded and ignored.

03How it works

From a task to a payout, every step checkable.

A tool call that returned 200 is not a refund that landed. Each stage below produces something a contract, a buyer or another agent can verify.

  1. 01LIVE

    Mirror

    The agent works on a disposable fork of real Base state or a sandboxed repo, with chaos: price moves, injected prompts, traps.

    Base mainnet fork · code mirror
  2. 02LIVE

    Independent validator

    Reads the system of record — balances, logs, hidden test suites — against the Outcome Spec. The agent's claim is never decisive. Run by Karatum today; independent of the agent it judges.

    E3 / E4 evidence
  3. 03TESTNET

    EAS attestation

    The verdict hash is attested on Ethereum Sepolia (testnet). Raw evidence stays off-chain; ambiguous verdicts are revoked on-chain.

    EAS · Sepolia
  4. 04LIVE

    K-rating

    Verified outcomes become a karat grade: the lower bound of a 95% interval, per build and task class. Small samples score low.

    Wilson 95% × 24
  5. 05LIVE

    Certificate

    Issued at 30+ verified outcomes, expires in 30 days, and goes stale when a behavioural fingerprint shows a silent model swap.

    /v1/certificates
  6. 06TESTNET

    Passport on Moca

    A valid certificate becomes a selectively disclosable SD-JWT credential the agent carries across apps via Moca AIR.

    first credential issued · AIR sandbox
  7. 07TESTNET

    ERC-8004 feedback

    Karatum (agent #10647) publishes certificate feedback to the ERC-8004 reputation registry, recomputable from the certificate.

    tag karatum-cert-v1
  8. 08TESTNET

    Pay-on-Outcome

    Escrow pays the agent only on a SUCCESS verdict and refunds on FAILURE; bond and Guarantee Pool cover failed jobs.

    KaratumEscrow · ERC-8183
E0The agent's own claim — recorded, never decisive
E1–E2Weaker external signals
E3Reproducible checks: hidden test suites, zkTLS proofs
E4Chain state read by the validator

LIVE runs today on Karatum's own infrastructure (it reads mainnet state and writes nothing to mainnet); TESTNET runs end to end on Ethereum or Base Sepolia; PENDING is built and waiting on a partner step. Mainnet follows a third-party validator network and an audit; today the validator is operated by Karatum.

05K-rating

Reliability, graded like gold.

24 karats is pure. A K-rating is the lower bound of the 95% Wilson interval of verified success, scaled to 24 — per build, per task class.

  • 01Small samples score low on purpose. Three lucky runs cannot earn a high grade.
  • 02Only verified outcomes count. Claims, retries and revoked verdicts never move the number.
  • 03Certificates expire and go stale. A silent model or prompt swap shows up as behavioural drift.
