It's a pay-per-call MCP oracle gateway offering verifiable randomness, delay proofs, trust-graph reputation scoring, and tool discovery — with offline-verifiable outputs.

  • Verifiable randomness (Platon): get_random draws unbiased, Ed25519-signed random bytes (with optional client seed); get_randomness_beacon returns a shared round-wide seed; ask_oracle gets a grounded read-only answer; verify_random checks a draw's signature offline (~$0.001–$0.004/call).

  • Provable delay (Chronos): compute_vdf runs a Wesolowski VDF over an RSA modulus to attest real sequential work (T = 1–1,000,000 squarings); verify_vdf confirms it in one exponentiation (~$0.01 / $0.001).

  • Reputation scoring (LUMEN): get_reputation_scores computes PageRank/EigenTrust scores over a directed weighted trust graph (up to 100k nodes); get_agent_trust returns one node's score, rank, and percentile; verify_reputation re-derives and confirms scores (plus optional graph commitment).

  • Discovery: list_oracle_capabilities (free) enumerates every tool with its capabilityId and per-call USD price — call it first.

  • Safety/commerce: pay-per-call via AIMarket Hub; all results are independently verifiable (signatures, VDF proofs, deterministic replay) rather than requiring trust in the service. Note: the README advertises 35 tools across 17 oracle families (e.g. consensus, routing, cascade risk, topology, spectral, time-lock); this schema exposes 9.

Provides access to LUMEN reputation scores (PageRank/EigenTrust trust scores) over a supplied graph.

  1. Click on "Deploy Server".

  2. Wait a few minutes for the server to deploy. Once ready, it will show a "Started" state.

  3. In the chat, type @ followed by the MCP server name and your instructions, e.g., "@aimarket-oracle-gateway Generate a provably random number for my raffle."

That's it! The server will respond to your query, and you can continue using it as needed.

compute_vdfA

Evaluate a Verifiable Delay Function (Chronos) — proof that real sequential work elapsed.

Use when you need provable, unforgeable elapsed time / sequential work: timed reveals, fair
ordering, proof-of-elapsed-time, randomness that cannot be precomputed. Producing the output
requires `T` sequential squarings over an RSA-2048 modulus (no shortcut), so a valid proof
attests the delay actually happened. Verify cheaply with `verify_vdf`.

Returns:
    The standard envelope; `result` contains:
      - `scheme`, `g`, `y` (= g^(2^T) mod N), `proof` (`{pi, l}`, Wesolowski), `modulus`.
    `verifiable.has_proof` will be true. Cost ~$0.01 USDC.

Example:
    compute_vdf(seed="0x1234abcd", difficulty=100000)
NameRequiredDescriptionDefault
seedYesSeed (hex) the VDF is evaluated over; it binds the generator g, so the output is tied to this input.
difficultyNoT — the number of sequential squarings to perform (1..1_000_000). Higher T = more wall-clock work that cannot be parallelized/GPU-accelerated, i.e. a longer provable delay. ~1000 is a fast demo; tune T to the delay you need.

Use this when you need randomness an autonomous agent cannot bias or predict and that a third
