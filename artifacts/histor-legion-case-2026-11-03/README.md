# HISTOR и LEGION-tlog на одном MCP-сервере

[English](README.en.md) · [Русский](README.md) · [Español](README.es.md) · [Français](README.fr.md) · [简体中文](README.zh.md)

Кейс выбран из [сверки от 2 ноября](../peer-xcheck-legion-atpp-2026-11-02/README.md). У сервера `com.aiapplyd/aiapplyd` один endpoint в выборке HISTOR, `https://mcp.aiapplyd.com/mcp`. Для него доступны определения до и после перехода и независимые хеши каждого инструмента.

## Зачем сравнивать

Вопрос кейса — можно ли по двум независимо собранным журналам прозрачности восстановить, какие определения инструментов один MCP-сервер объявлял в разные моменты. LEGION-tlog выбран за время наблюдения и отдельный SHA-256 для каждого инструмента. Сначала сопоставляем записи по времени и проверяем совпадение. Затем сравниваем ту же запись LEGION с более поздними наборами HISTOR и показываем, что именно изменилось.

Верификация подписей и доказательств включения привязывает сравнение к конкретным записям каждого журнала. Результат относится к объявленным определениям и выбранным моментам наблюдения. Безопасность сервера и полнота наблюдений требуют отдельных проверок.

## Повторить

```sh
cd artifacts/histor-legion-case-2026-11-03
node replay.mjs > /tmp/histor-legion-result.json
diff -u result.json /tmp/histor-legion-result.json
```

Проверено на Node.js 22. Достаточно сохранённых файлов. Скрипт пересчитывает SHA-256 для канонического JSON полей name, description и inputSchema и сравнивает карты хешей. Входные данные взяты из архивов сверки 2 ноября. histor.json содержит три набора определений из снимка HISTOR и историю переходов. legion.json содержит сохранённый ответ публичного API LEGION.

| Состояние HISTOR | Совпадает с записью LEGION | Только HISTOR | Только LEGION |
|---|---:|---:|---:|
| С 19 октября 21:37:07 UTC, включая чтение LEGION в 22:01:05 UTC | 23 | 0 | 0 |
| Переход 24 октября 18:19:21 UTC | 0 | 23 | 23 |
| Последнее чтение в снимке 2 ноября, 07:09:47 UTC | 0 | 40 | 23 |

После перехода у всех 23 имён одинаковый суффикс и новый префикс getmattered_ вместо aiapplyd_. Совпадение суффиксов не устанавливает эквивалентность поведения. Новейшая запись LEGION в сохранённом ответе датирована 19 октября. Кейс сравнивает архивные наблюдения, не текущие состояния. Он не устанавливает причину отсутствия новой записи в LEGION. Скрипт проверяет подписи и включение для обоих журналов, привязывает сохранённые определения к подписанным меткам HISTOR и повторяет сверку хешей инструментов.

## Проверка подписи и включения LEGION

Для листа 29030 сохранены публичные ответы от 3 ноября. Файлы `record.json`, `inclusion.json`, `head.json` и `keyring.jsonl` получены из `/tlog/v0/records/29030`, `/tlog/v0/proof/inclusion?leaf_index=29030`, `/tlog/v0/head/50578` и `/tlog/v0/keyring` соответственно.

Один запуск проверяет совпадение листа с архивом от 2 ноября, закреплённый SHA-256 отпечаток корневого ключа, цепочку регистраций ключей, подписи Ed25519 листа и подписанной вершины дерева и путь включения из 16 хешей по RFC 9162. Лист 29030 входит в дерево из 50 578 листьев с подписанной вершиной дерева от 3 ноября 11:46:04 UTC. Корень приведён в result.json. Корневая регистрация обрабатывается как закреплённая начальная запись по правилам LEGION. Скрипт предназначен для этого снимка и отклоняет события отзыва ключей.

Проверка подтверждает включение в дерево, подписанное LEGION. Bitcoin-якорь и согласованность с другими вершинами дерева здесь не проверялись. [Спецификация LEGION](https://legion-api.com/tlog/docs/).

## Проверка подписи и включения HISTOR

`histor-transitions.json` фиксирует происхождение идентификаторов меток из архивного changes.jsonl.gz. `histor-issuer.json` и `histor-head.json` получены из /api/v1/issuer и /api/v1/log/sth. Для каждого labelId сохранены /api/v1/labels/{labelId} и /api/v1/labels/{labelId}/proof?tree_size=1564894.

Закреплённый did:key совпадает с ключом в сохранённом манифесте от 2 ноября. Скрипт проверяет Ed25519-подпись вершины дерева, подписи AWR/2 eddsa-jcs-2022 трёх меток и их включение по RFC 9162. Для каждой метки проверяются имя сервера, время наблюдения, число инструментов и SHA-256 канонического набора определений. В снимке от 2 ноября набор из 40 инструментов привязан к метке изменения от 31 октября. Время последнего чтения 2 ноября берётся из метаданных снимка. Оно отдельно этой меткой не подписано.

Три листа HISTOR: 762851, 988911 и 1324412. Общая подписанная вершина дерева от 3 ноября 17:53:27 UTC покрывает 1 564 894 листа. Проверка относится к сохранённым вершинам дерева и выбранным меткам.
