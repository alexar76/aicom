Thank you for checking each release against the wheels and for the new records.

You are right about the versions: aimarket-platon 0.1.4 and aimarket-oracle-core 0.6.1 never reached
PyPI, so 0.1.5 and 0.6.2 are the first published fixes; please disregard our note on 000615.

The nine open records are fixed to the six goals you set, and the releases are on PyPI: aimarket-mcp
0.6.4, aimarket-metis 0.2.5, aimarket-treasury 0.1.4, aimarket-platon 0.1.6, aimarket-oracle-core 0.6.3,
aimarket-logos 0.2.2 and skopos-fleet 0.2.3, with aimarket-hub 3.16.1 for the last goal:

- Address headers count only from `*_TRUSTED_PROXIES`, which defaults to loopback and takes addresses,
  CIDRs, host names and `gateway` (000636–000638). We made the same change in aimarket-atlas 0.3.3 and in
  skopos-fleet, which had the same pattern.
- A keyless server no longer infers "local": keyless access to protected HTTP operations is refused by
  default, local callers included.
  A proxy or tunnel running as the server's own user cannot be told from a local client, so local TCP is
  trusted only when the operator opts in with `*_LOCAL_RELAY=1`, and where the socket owner cannot be read
  (macOS, Windows) only with `*_LOCAL_UNVERIFIED=1` as well; otherwise the request is refused
  (000640–000643).
- For remediation Git operations using SKOPOS's configured SSH key, host keys are pinned on first use
  and changed keys are rejected, single-label remotes included. Only a loopback Gitea may skip this
  check, with `SKOPOS_GIT_SKIP_HOST_KEY_LOOPBACK=1` (000639). Without an explicit SSH key path, the
  operator's Git/SSH configuration applies.
- A browser with a valid, unexpired signed remember-me cookie restores its session before any
  lockout check, so the login budget never reaches it. An unknown client over the all-addresses budget is
  slowed down, not refused: its submitted login waits once (at most a minute) and is then checked, so
  failures from other addresses cannot lock the operator out. An address that logged in successfully
  within `SKOPOS_LOGIN_KNOWN_DAYS` does not wait (000644).
- logos binds 127.0.0.1 unless `LOGOS_HOST` says otherwise (000638).
- aimarket-hub 3.16.1 sends an oracle its paid-tier secret as `X-AIMarket-Paid-Tier`, so the oracle can
  sell its paid tier without trusting the hub's address. The hub sends it only for a call it funded (a
  positive price reserved on a channel or credit account, or a verified x402 payment), never for
  sandbox trials or routing fees alone. A positively priced call reserved against promotional credits
  is funded. Credentials are selected only for explicitly configured exact invoke URLs in
  `AIMARKET_ORACLE_PAID_TIER_CREDENTIALS`; one secret may be assigned to multiple explicit URLs,
  including a configured transport rewrite. Credentials travel over HTTPS unless the destination
  entry allows HTTP, never follow a redirect or an environment proxy, and a buyer's own
  `X-AIMarket-Paid-Tier` header is dropped. Matching secrets must be configured on both hub and oracle.

Correction after rechecking the published SKOPOS wheel: 0.2.2 still had a dashboard fallback that
trusted address headers when its old Tornado peer lookup failed on Streamlit 1.66.1. In 0.2.3 the
dashboard reads the actual Uvicorn socket peer, before any forwarded-header rewrite, and applies
`SKOPOS_TRUSTED_PROXIES` to that peer. If the transport peer is unavailable or invalid, all such
requests use the shared `unknown` bucket and address headers are ignored. This closes the remaining
dashboard address-trust issue in GCVE-110-PYPI-2026-021896. The SSH change for 000639 and the bounded
shared login delay for 000644 first shipped in 0.2.2 and remain in 0.2.3.

Each release's changelog names its record; the hub change is described in the aimarket-hub 3.16.1 release
notes. Could you mark these versions as fixed in 000636–000644?
