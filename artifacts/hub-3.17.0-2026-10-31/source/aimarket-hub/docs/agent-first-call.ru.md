# Первый вызов агента: обнаружение → вызов → верификация

[English](agent-first-call.md) · [Русский](agent-first-call.ru.md) · [Español](agent-first-call.es.md) · [Français](agent-first-call.fr.md) · [中文](agent-first-call.zh.md)

Выберите привычный клиент. MCP и A2A дают доступ к одному маркетплейсу и общим механизмам контроля вызовов; подключать оба протокола не требуется.

## MCP-клиент

Добавьте `https://modelmarket.dev/mcp` в MCP-клиент с поддержкой Streamable-HTTP. Получите актуальные схемы аргументов через `tools/list`, затем дайте агенту задание:

> Найди погоду GAIA Open-Meteo через `market_search`. Покажи цену и схему входных данных выбранного предложения. Выполни `market_invoke` для `device_id` `om-wx-01`, скопировав `product_id`, `capability_id` и `source_hub` из предложения. Используй бесплатную пробу; если потребуется оплата, остановись. Покажи результат и квитанцию. Укажи результат верификации квитанции отдельно от успешности выполнения: наличие поля подписи ещё не означает, что верификация пройдена.

Сохраняйте `source_hub`: федеративное предложение нужно вызывать с указанием его источника. При исчерпании бесплатной пробы размещённый сервис может вернуть `429 trial_quota_exhausted`. Подробнее — в [документации MCP](https://github.com/alexar76/aicom/blob/main/docs/hosted-mcp-endpoint.md). Пример A2A ниже явно верифицирует подпись на стороне клиента.

## Агент A2A

Общий [пример на Python](../examples/first-agent-call.py) получает Agent Card, ищет `gaia.weather.read@v1`, сохраняет хаб-источник и ограничивает цену одного вызова суммой $0.01. Запускайте из каталога `aimarket-hub`, используя Python 3.11+:

```bash
python -m pip install 'aimarket-agent>=2.4.0'
```

```bash
python examples/first-agent-call.py
python examples/first-agent-call.py --invoke
```

Первая команда выполняет только поиск. Вторая делает один вызов. Без `AIMARKET_KEY` используется доступная бесплатная проба. Для сценария оплаты предоплаченными кредитами задайте в `AIMARKET_KEY` API-ключ аккаунта с пополненным балансом: вызов может списать до $0.01. Не сохраняйте ключ в скриптах или коммитах. Переменная `AIMARKET_HUB_URL` позволяет выбрать другой хаб.

Пример передаёт `device_id` `om-wx-01` в предложение GAIA Open-Meteo. Если каталог изменился, сверьте схему входных данных в ответе поиска. Если нужного предложения нет, пример завершится без вызова.

## Продолжение Task с оплатой x402

После кода `2` изучите условия оплаты в Task. Один раз оплатите выставленный счёт через свой кошелёк, дождитесь расчёта и используйте ниже прежний Task ID и хеш транзакции. Пример предъявляет уже выполненный перевод: он не подписывает, не отправляет и не заменяет транзакцию. Для Task аккаунта нужен прежний `AIMARKET_KEY`. Чтение завершённого Task не повторяет оплату или вызов.

Исправление продолжения x402 находится в этом рабочем каталоге `aicom`. До выпуска исправления в SDK установите локальный клиент из каталога `aimarket-hub`:

```bash
python -m pip install -e ../aimarket-agent
```

```bash
python examples/first-agent-call.py --task-id a2at_... --payment-tx 0x...
python examples/first-agent-call.py --task-id a2at_...
```

## Как читать результат

- Код `0` после `--invoke`: получен `TASK_STATE_COMPLETED`, а `receipt_verified` равен true. SDK верифицировал квитанцию по ключу подписанта; для федеративного предложения используется ключ поставщика. Только после этого выводится результат.
- Код `1`: предложение погоды недоступно.
- Код `2`: Task не завершён. `TASK_STATE_INPUT_REQUIRED` может означать необходимость оплаты, `TASK_STATE_AUTH_REQUIRED` — необходимость учётных данных. Изучите выведенный статус и [руководство по оплате](a2a.md#invoke).
- Код `3`: выполнение завершено, но верификация квитанции не пройдена либо квитанция отсутствует. Такой результат нельзя считать верифицированным.
- Код `4`: квитанция валидна, но погодный результат отсутствует. Одних успешного выполнения и верификации подписи недостаточно для успешного завершения примера.

Код `0` при поиске без `--invoke` подтверждает только обнаружение. Ошибки сети или протокола также останавливают пример. Он не пополняет аккаунт, не переводит средства, не продолжает оплату и не повторяет вызов автоматически. Незавершённый Task сам по себе не доказывает отсутствие списания: изучите статус перед повтором. Для намеренных повторов используйте прежний `message_id`, как описано в [руководстве A2A](a2a.md).

Валидная квитанция подтверждает подлинность подписанной записи. Она не доказывает независимо, что погодные данные достоверны. Лимиты бесплатной пробы и доступность предложений определяет хаб; пример их не гарантирует.
