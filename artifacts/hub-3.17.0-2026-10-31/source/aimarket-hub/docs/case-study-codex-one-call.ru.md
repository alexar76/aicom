# Codex: одна клиентская операция и два платных субподрядчика

[English](case-study-codex-one-call.md) · [Русский](case-study-codex-one-call.ru.md) · [Español](case-study-codex-one-call.es.md) · [Français](case-study-codex-one-call.fr.md) · [中文](case-study-codex-one-call.zh.md)

**30 сентября 2026 года** Codex повторил тест субподряда GAIA через новый клиент `await run_pipeline(...)`, с тем же предоставленным оператором кошельком и **общим лимитом $1**. На хабе работал образ `modelmarket-hub:prod-20260930-onecall`. Оба ребёнка завершились успешно, клиент автоматически дождался подтверждений. Услуги стоили **0.002 USDC**, полный измеренный расход с газом — **≈ $0.00468270**.

## Порядок запуска и фактические запросы

Клиент вызвал `POST /studio/prepare-pipeline` с графом и кошельком, проверил граф, условия платежей, балансы и запас на комиссии, подписал платежи локально, приватно сохранил пакет и вызвал `pipeline.run@v1`. Административные учётные данные и закрытый ключ хабу не передавались. Заказ выполнялся через публичный REST API из Python в терминале Codex, не через MCP. Вызывающий код ожидал одну SDK-операцию и вручную resume не запускал.

| Порядок | Запрос к хабу | HTTP | Состояние |
|---|---|---:|---|
| 1 | `POST /studio/prepare-pipeline` | 200 | `ready` |
| 2 | `POST /ai-market/v2/invoke` | 202 | `active` |
| 3 | `POST /ai-market/v2/invoke` | 202 | `active` |
| 4 | `POST /ai-market/v2/invoke` | 200 | `completed` |

Платный тест выполнил **четыре запроса к хабу**, а не ровно два. Запросы к RPC блокчейна и курсу идут дополнительно. Первый ответ подготовки содержал и котировку, и авторизации. После каждого 202 продолжался тот же run с идентичным подписанным пакетом. Создан один корневой job и выполнены два дочерних вызова. После завершения `run_pipeline(resume=True, ...)` вернул тот же локально сохранённый результат с **нулём дополнительных запросов к хабу**. Тест с проверкой доказательств занял 11.872 секунды; это наблюдение, не гарантия задержки.

## Граф и результат

Граф купил `gaia.weather.read@v1`, затем `gaia.air.read@v1` продукта `gaia.gateway`, с `source_hub: https://iot.modelmarket.dev` и `city: Berlin`. Шаг `air` зависел от завершения `weather`; погодные значения на вход воздуха не передавались. Итог — подписанное показание **GAIA-AQ1 (ретранслятор Open-Meteo AQ)**, устройство `om-aq-01`, на **2026-09-30 04:24:34 UTC**. ## Дополнительные проверки

Бесплатный граф LOGOS из двух шагов прошёл через тот же SDK без кошелька, RPC и потолка курса, ровно за два запроса к хабу. Платный граф с общим бюджетом $0.003 прошёл проверку цены услуг, но был локально отклонён из-за нехватки запаса на комиссии: один запрос подготовки, ни одного root invoke, ни одного платежа. Локально прошли **84 теста** и ещё **4 платёжных теста Anvil**. Проверены потеря ответа, идентичные повторы, восстановление без signer после подписания, отказ по бюджету газа, неверная сеть или авторизация, файловая блокировка и терминальный отказ ребёнка.

CLI также выполнил бесплатный граф на проде, затем при resume вернул идентичный сохранённый результат без ключа кошелька.

Обе транзакции успешны. Суммы переводов USDC и сетевых комиссий совпали с изменениями балансов покупателя. Подписи корня и счёта проверены по ключу хаба, записанному до теста, вместе с хешами счёта/результата и двумя ссылками на дочерние квитанции. Подпись показания воздуха проверена по вложенному ключу; независимая привязка ключа устройства не устанавливалась. Публичный пакет содержит подписанные результаты и квитанции сети, но не закрытый ключ, токен запуска или сырые подписанные платёжные транзакции.

Это по-прежнему разрешённый оператором интеграционный тест: GAIA и Hub находятся в одной управляемой экосистеме, Hub выступает продавцом по расчётам. Тест подтверждает реальную оплату и субподряд, но не спрос независимых клиентов. SUB/1 связывает работы; источник средств — `buyer_wallet`, у детей `funded_by: own`, кредитный allowance не использовался. Смарт-контракты не передеплоивались. Бесплатный тест SDK не подтверждает работоспособность отдельно настраиваемого старого маршрута `/studio/run`.

## Продолжение: контракт независимого продавца, 3.10.1

Codex добавил SELLER-OP/1 и выложил хаб с миграциями 44–45. Подробный протокол и ограничения описаны в руководстве по цепочкам. Пройдены **223 целевые проверки и 6 сценариев локального Anvil**, включая два расчёта между отдельными хабами с одноразовым токеном, один — с потерянным ответом продавца. В каждом таком сценарии покупатель заплатил ровно 4 000 единиц токена один раз; счёт создавался и погашался у продавца. Это интеграционные тесты локальной сети, а не новые покупки в mainnet.

На production проверены подписанный манифест, wheel и пять руководств, бесплатная цепочка MCP, бесплатная цепочка SDK с двумя основными запросами и чтение прежнего платного заказа только через GET. Новых mainnet-платежей из тестового кошелька не отправляли. У локального weather.witness нет поддерживаемого маршрута прямой выплаты: подготовка предложения теперь корректно возвращает 409/settlement_route_unsupported вместо 500, до работы и оплаты. Прежний кредитный контракт SUB/1 этого SKU не меняется. Независимый production-peer в этом тесте не обновлялся и не покупался; этот путь проверен на двух контролируемых хабах с Anvil.

[Обезличенные доказательства проверки](evidence/seller-operations-2026-09-30.json). Закрытые ключи, operation token и подписанные платёжные пакеты не публикуются.
