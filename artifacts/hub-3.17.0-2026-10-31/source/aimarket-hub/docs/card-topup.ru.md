# Покупка кредитов картой (Stripe Checkout)

> **English:** [card-topup.md](./card-topup.md) · **Español:** [card-topup.es.md](./card-topup.es.md) · **Français:** [card-topup.fr.md](./card-topup.fr.md) · **中文:** [card-topup.zh.md](./card-topup.zh.md)
>
> Код: [`card_topup.py`](../aimarket_hub/card_topup.py) · маршруты в [`hub_routes/accounts.py`](../aimarket_hub/hub_routes/accounts.py) · [`credits.py`](../aimarket_hub/credits.py) (`deposit`) · тесты [`test_card_topup.py`](../tests/test_card_topup.py)

[Пополнение за USDC](credits-topup.ru.md) позволяет агенту с кошельком пополнить кредитный
аккаунт. Человек с картой и без кошелька этого не мог. Эта дверь принимает карту, как любой
магазин, и кладёт деньги на **ту же** строку журнала, что и пополнение за USDC
(`CreditsLedger.deposit`, вид `topup`). Поэтому дальше всё на кредитном рельсе — платные вызовы,
[мандаты](mandates.ru.md), субподряд, A2A — работает так же.

**Статус.** В хабе с 2026-10-20 (3.16.0), **по умолчанию выключено**. В официальной песочнице Stripe 20–21 октября 2026 года проверены оплата без налога, оплата Managed Payments с ненулевым НДС, полные возвраты с налогом и без него, а также спор. Ниже точно указаны покрытие и оставшиеся пробелы. Настоящие деньги не перемещались.

<a id="sandbox-verification"></a>
## Что проверено в официальной песочнице Stripe

Использовались размещённый у Stripe Checkout, тестовые карты, настоящие ответы Stripe API и подписанные события, доставленные официальным Stripe CLI в изолированный локальный хаб. Это отдельные проверки, а не модульные тесты с подменой Stripe на границе HTTP. В [протоколе проверки](evidence/stripe-sandbox-2026-10-21.json) сохранены суммы, ID событий, результаты доставки и сверка журнала; время в протоколе — UTC.

| Сценарий | Подтверждённый результат |
|---|---|
| `off`: оплата без налога | Оплачено $5, через `checkout.session.completed` зачислено ровно $5 один раз; повторная доставка не добавила кредит. |
| `stripe_tax` | В песочнице проверено создание и открытие Checkout. Оплата, ненулевой налог, возврат и спор в этом режиме **не проверены**. |
| `managed_payments` + `exclusive` | Тестовый покупатель из Нидерландов: $5 + НДС 21% ($1,05) = $6,05 USD; `paid`, расчёт налога `complete`, ответственность `stripe`. Через `refresh` хаб зачислил ровно $5 один раз. Webhook первоначальной оплаты в том прогоне не проверялся. |
| Полный возврат с налогом | Stripe API вернул `succeeded` на $6,05, включая $1,05 налога. Подписанный `charge.refunded` получил HTTP 200 и перевёл пополнение в `refunded`. Возврат запросил оператор; автоматический возврат по инициативе Stripe не проверялся. |
| Полный возврат без налога (`off`) | Возвращено $5, статус `succeeded`; подписанный `charge.refunded` получил HTTP 200 и перевёл пополнение в `refunded`. |
| Спор без налога (`off`) | Карта `4000 0000 0000 0259` создала настоящий sandbox-спор на $5: причина `fraudulent`, статус Stripe `needs_response`; `charge.dispute.created` перевёл пополнение в `disputed`. |
| Повторные и запоздалые события | Stripe повторно доставил события оплаты, возврата и спора. Статусы `refunded`/`disputed` сохранились после позднего события оплаты; на каждом аккаунте осталась одна запись `topup` на $5, повторного кредита нет. |
| Налог внутри цены (`inclusive`) | Проверка сумм покрыта локальными тестами; оплаченный Checkout и его возврат в официальной песочнице **не проверены**. |

**Найден и исправлен баг порядка событий.** В первом прогоне Stripe доставил спор до завершения оплаты; прежний обработчик ответил `ignored`. Теперь хаб находит Checkout Session по PaymentIntent, проверяет связь с локальным пополнением и сверяет оплату по сохранённому налоговому режиму перед записью возврата или спора. При сбое поиска возвращается ошибка с возможностью повтора. Затем настоящий возврат намеренно доставили раньше события оплаты: возврат записался, а поздняя доставка оплаты от Stripe сохранила `refunded`. Ранний спор также покрыт регрессионным тестом; повторная доставка восстановила первый спор, новый прогон оплаты со спором прошёл. Проверки ID сессии и сумм сохранены.

**Поведение баланса подтверждено:** возврат и спор фиксируют статус и пишут аккаунт в журнал ошибок, но автоматически не снимают кредит и не блокируют аккаунт. На каждом проверенном аккаунте осталось $5. Решение о корректировке баланса и сама корректировка остаются за оператором.

**Не проверены в официальной песочнице:** частичный возврат, асинхронный неуспешный возврат, выигрыш/проигрыш спора, спор в Managed Payments, оплата и возврат в `stripe_tax` и `inclusive`. Успех в sandbox не подтверждает право использовать Managed Payments в production; боевой режим выбирает оператор.

Источники: [тестовые карты и споры Stripe](https://docs.stripe.com/testing#disputes), [API возвратов](https://docs.stripe.com/api/refunds/create), [поиск Checkout Session по PaymentIntent](https://docs.stripe.com/api/checkout/sessions/list).

## Коротко

```bash
# 1. Открыть оплату на $10 кредита для своего аккаунта.
curl -s -X POST $HUB/ai-market/v2/account/topup/card -H "X-API-Key: $KEY" \
     -H 'Content-Type: application/json' -d '{"amount_usd": 10}'
# → 201 {"topup_id": "ctp_…", "checkout_url": "https://checkout.stripe.com/…", "status": "open",
#        "amount_usd": 10, "charge_usd": 10, "fee_usd": 0, "expires_at": "…", "status_url": "…"}

# 2. Человек открывает checkout_url и платит. Stripe возвращает его на status_url.

# 3. Кредит зачисляется, когда Stripe подтверждает оплату; статус можно читать в любой момент:
curl -s $HUB/ai-market/v2/card-topups/ctp_…
```

Агент сам картой не платит: он передаёт `checkout_url` своему человеку и ждёт (или опрашивает
статус). В этом и смысл двери: платит человек, а агент тратит в пределах своего
[мандата](mandates.ru.md).

## Что видит покупатель

Страницу Stripe (`checkout.stripe.com`) с одной строкой: «Prepaid credit on <хост хаба>: $10.00»
(и «incl. $x card fee», если оператор задал наценку). Если включён налоговый режим, страница ещё
спрашивает адрес для счёта и показывает налог; при Managed Payments видны условия и имя продавца
Stripe. Страница живёт **один час**; новая оплата — один запрос. После оплаты Stripe отправляет
покупателя на `status_url`, где хаб отвечает JSON со статусом пополнения.

Номер карты до хаба не доходит никогда — хаб его просто не видит. Требования PCI остаются на Stripe.

## Что проверяет хаб

Stripe вызывает `POST /ai-market/v2/stripe/webhook`. Прежде чем читать событие, хаб проверяет
`Stripe-Signature`: HMAC-SHA256 над `t.payload` секретом endpoint, `t` не старше пяти минут,
сравнение за постоянное время (пока секрет меняется, принимается несколько подписей `v1`). Затем
сессия из события сверяется со строкой, которую открыл хаб, — и никогда наоборот:

| Проверка | Зачем |
|---|---|
| `topup_id` — тот, что открыл этот хаб | событие называет пополнение, но создать его не может |
| id сессии совпадает с тем, что Stripe выдал при открытии | оплаченную сессию другой оплаты нельзя выдать за эту |
| `payment_status == "paid"` | завершённая, но не оплаченная (асинхронная) сессия пока ничего не зачисляет |
| `currency == "usd"` и суммы совпадают с запрошенной хабом — по налоговому режиму, с которым открыта оплата ([ниже](#налог-с-продаж-три-режима)) | сумма и аккаунт — хаба, а не события |
| с боевым ключом (`sk_live_…`, `rk_live_…`) сессия обязана быть `livemode` | тестовые деньги никогда не зачисляются на боевом хабе |

Кредит идёт на аккаунт, привязанный при открытии оплаты, на запрошенную сумму. Наценка за карту и
налог не зачисляются. Строка журнала ссылается на id сессии, поэтому повторная доставка события —
или две доставки наперегонки — зачисляют один раз. Stripe узнаёт id пополнения, но не аккаунт.

События о чём-то другом получают ответ `200` и пропускаются, чтобы Stripe не слал их днями.
`checkout.session.expired` закрывает строку.

## Налог с продаж: три режима

Кто считает и платит налог с продаж (НДС/VAT, GST, sales tax в США) — решение оператора. Это одна
настройка, `AIMARKET_CARD_TOPUP_TAX`, а хаб запоминает режим **в строке каждой оплаты**: оплата,
открытая в одном режиме, проверяется по нему же, даже если оператор поменял настройку до оплаты.

| Режим | Продавец | Кто считает налог | Кто сдаёт отчётность и платит | Комиссия Stripe сверх карточной |
|---|---|---|---|---|
| `off` (по умолчанию) | оператор | никто, в Stripe | оператор, вне Stripe | — |
| `stripe_tax` | оператор | Stripe Tax, по адресу покупателя | оператор (Stripe Tax готовит отчёты) | по тарифу Stripe Tax |
| `managed_payments` | **Stripe** (продавец по закону, merchant of record) | Stripe | Stripe | 3,5 % с операции |

**Что меняется в оплате, которую открывает хаб:**

| Режим | Дополнительные параметры Checkout Session | Версия API |
|---|---|---|
| `off` | нет | `2024-06-20` |
| `stripe_tax` | `automatic_tax[enabled]=true`, `billing_address_collection=required`, `price_data[tax_behavior]`, `product_data[tax_code]` | `2024-06-20` |
| `managed_payments` | `managed_payments[enabled]=true`, `price_data[tax_behavior]`, `product_data[tax_code]`. Без `automatic_tax`, `billing_address_collection` и параметров способов оплаты: рядом с Managed Payments Stripe их отклоняет — адрес он собирает и способы оплаты выбирает сам. | `2025-03-31.basil` (самая ранняя, где есть Managed Payments); в ней же хаб и читает такую оплату |

**Налог сверху или внутри цены.** `AIMARKET_CARD_TOPUP_TAX_BEHAVIOR`:

- `exclusive` (по умолчанию) — налог добавляется сверху. Пополнение на $10 для покупателя из страны
  с НДС 21 % стоит ему $12.10. Хаб проверяет, что `amount_subtotal` сессии ровно $10, а
  `amount_total` ровно `amount_subtotal + total_details.amount_tax` — никакая скидка или другая
  строка сумму сдвинуть не может. Зачисляется $10 кредита, а $2.10 записываются в строку как `tax_usd`.
- `inclusive` — налог внутри цены. Покупатель платит $10, налог входит в них, оператор получает
  меньше. Хаб проверяет, что `amount_total` ровно $10 и налог не отрицательный. Зачисляется $10 кредита.

**Налоговый код товара** — `AIMARKET_CARD_TOPUP_TAX_CODE`, по умолчанию `txcd_10000000` («General —
Electronically Supplied Services», электронные услуги в целом). Для маркетплейса ИИ-возможностей
могут лучше подойти `txcd_10105002` («ИИ как услуга — облачный — для бизнеса») или `txcd_10701410`
(«Информационные услуги в электронном виде — для бизнеса»); правильный код — вопрос к бухгалтеру
оператора. При Managed Payments код обязан быть из списка Stripe «Eligible for Managed Payments».

**Настройка, которую хаб не понимает, закрывает дверь** — хаб не открывает оплаты наугад:
неизвестный режим, налоговый код не в виде `txcd_` + 8 цифр или поведение не
`exclusive`/`inclusive` — и well-known показывает `"enabled": false` с причиной.

**Что видят покупатель и well-known.** `payment_rails.credits.topup_card.tax` — это
`{"mode": "off"}` или `{"mode", "behavior", "seller_of_record": "operator" | "stripe"}`. После оплаты
статус пополнения содержит `tax: {mode, behavior, tax_usd}`.

### Managed Payments: прочитать до включения

Кого допустить, решает Stripe, и его условия здесь важны:

- **Только прямые продажи.** На странице допуска Stripe сказано, что продукт продаётся «напрямую
  покупателям, а не через платформу или маркетплейс». Хаб — маркетплейс: купленный здесь кредит
  тратится на возможности независимых поставщиков. Примет ли Stripe предоплаченный кредит
  маркетплейса в Managed Payments — решать Stripe; спросите у Stripe до того, как на это полагаться.
- **Только цифровые автоматические продукты** с допустимым налоговым кодом; бизнес зарегистрирован
  в поддерживаемой стране (в списке страны ЕС, Великобритания, Швейцария, Норвегия, США, Канада,
  Австралия, Гонконг, Япония, Сингапур).
- **Stripe может вернуть деньги** покупателю в течение 60 дней, чтобы не допустить chargeback, и
  применяет правила о «периоде охлаждения». Каждый такой возврат приходит в хаб как
  `charge.refunded` ([ниже](#возвраты-и-споры)).
- Включите Managed Payments в панели (Settings → Managed Payments) до того, как ставить режим, иначе
  Stripe откажется открыть оплату (`502 stripe_refused`, ничего не списано).

### Stripe Tax: до включения

В панели: Tax → настройки (адрес отправителя, налоговый код по умолчанию) и **регистрации** — Stripe
Tax собирает налог только там, где оператор зарегистрирован. Если для страны покупателя регистрации
нет, налог равен нулю, и хаб это принимает (`amount_tax: 0`).

## Если webhook не пришёл

`POST /ai-market/v2/card-topups/{id}/refresh` спрашивает у Stripe сессию и делает те же проверки.
Вызвать его может любой, у кого есть id (с ограничением частоты на вызывающего): зачислить он может
только на аккаунт, к которому привязана оплата. Поэтому оплаченное пополнение не теряется из-за
потерянной доставки.

## Возвраты и споры

- **`charge.refunded`** — возврат, сделанный в Stripe (оператором или, при Managed Payments, самим
  Stripe), переводит пополнение в `refunded` и пишет в лог ошибку с аккаунтом и суммой. Кредит
  **не** списывается автоматически: он мог быть уже потрачен, а уводить баланс в минус — решение, а
  не рефлекс. Оператор поправляет баланс вручную.
- **`charge.dispute.created`** — спор (chargeback) переводит пополнение в `disputed` и пишет ошибку в
  лог. Аккаунт автоматически не замораживается.

## Лимиты и настройки

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `AIMARKET_CARD_TOPUP_MIN_USD` | `5` | Наименьшее пополнение (не меньше $0.50 — минимума Stripe). |
| `AIMARKET_CARD_TOPUP_MAX_USD` | `100` | Наибольшее разовое пополнение. |
| `AIMARKET_CARD_TOPUP_DAILY_USD` | `200` | Сколько один аккаунт может купить картой за 24 часа. Открытые оплаты учитываются, пока не истекут (1 час), — любую из них ещё могут оплатить; возвращённое или оспоренное пополнение продолжает учитываться — его кредит остаётся на аккаунте. Оплаты, открытые в один момент, проверяются друг против друга: вместе превысить лимит они не могут. |
| `AIMARKET_CARD_TOPUP_FEE_PCT` | `0` | Наценка в процентах, показывается до оплаты и не зачисляется. `0` — комиссию за карту несёт оператор. Где наценка за карты ограничена законом, оставьте `0`. |
| `AIMARKET_CARD_TOPUP_FEE_FIXED_USD` | `0` | Фиксированная наценка за оплату. |
| `AIMARKET_CARD_TOPUP_TAX` | `off` | `off`, `stripe_tax` или `managed_payments` ([выше](#налог-с-продаж-три-режима)). |
| `AIMARKET_CARD_TOPUP_TAX_BEHAVIOR` | `exclusive` | `exclusive` (сверху) или `inclusive` (внутри цены). |
| `AIMARKET_CARD_TOPUP_TAX_CODE` | `txcd_10000000` | Налоговый код товара в Stripe. |

Дневной лимит — то, что ограничивает ущерб от украденной карты: спор приходит, когда кредит уже мог
быть потрачен, а потраченный кредит хаб вернуть не может.

## Чего эта дверь не делает

- **Не списывает кредит** после возврата или спора — это записывается в лог и правится вручную.
- **Не замораживает аккаунт** при споре.
- **Не выставляет счета.** Stripe сам присылает чек на e-mail плательщика, если это включено в
  аккаунте Stripe (при Managed Payments — всегда). Юридический счёт от имени оператора и учёт
  продажи — дело оператора и его юрисдикции.

## Оператору

### Как открыть дверь

1. Аккаунт Stripe на оператора. **Страну аккаунта потом не поменять**; для настоящих денег это
   должна быть страна юрлица, которое получает выплаты.
2. **Ограниченный ключ** с одним правом, *Checkout Sessions: Write* (Developers → API keys → Create
   restricted key → Custom permissions). Хабу больше ничего не нужно: открыть оплату и прочитать её.
   Положите его в `STRIPE_SECRET_KEY_FILE` (docker secret) или `STRIPE_SECRET_KEY`.
3. Webhook в панели: `https://<хаб>/ai-market/v2/stripe/webhook`, события
   `checkout.session.completed`, `checkout.session.async_payment_succeeded`,
   `checkout.session.expired`, `charge.dispute.created`, `charge.refunded`. Его секрет подписи — в
   `STRIPE_WEBHOOK_SECRET_FILE` (или `STRIPE_WEBHOOK_SECRET`).
4. `AIMARKET_CARD_TOPUP_ENABLED=1`; кредитный рельс должен быть включён (`AIMARKET_CREDITS_ENABLED=1`).
5. По желанию — налоговый режим (`AIMARKET_CARD_TOPUP_TAX`), после шагов этого режима в панели.

Well-known показывает, открыта ли дверь и почему нет: `payment_rails.credits.topup_card` =
`{"enabled", "provider": "stripe-checkout", "create", "status", "currency", "min_usd", "max_usd",
"daily_usd", "fee_pct", "fee_fixed_usd", "tax"}` или `{"enabled": false, "reason": "…"}`.

### Маршруты

| Маршрут | Кто | Что |
|---|---|---|
| `POST /ai-market/v2/account/topup/card` | `X-API-Key` аккаунта | открыть оплату (`{"amount_usd"}`) → `201` с `checkout_url`; 6 в минуту на аккаунт |
| `GET /ai-market/v2/card-topups/{id}` | любой, у кого есть id | статус; аккаунт — только его собственному ключу |
| `POST /ai-market/v2/card-topups/{id}/refresh` | любой, у кого есть id | сверка со Stripe, зачисление, если оплачено |
| `POST /ai-market/v2/stripe/webhook` | Stripe (с подписью) | события |
| `GET /ai-market/v2/account/topups` | ключ аккаунта | `card_topups` рядом с USDC-пополнениями `topups` |

### Ошибки

| Код | `error` | Значение |
|---|---|---|
| 400 | `amount_invalid`, `amount_out_of_range` | не целые центы или вне min/max |
| 400 | `signature_invalid` | подпись webhook не сошлась (ничего не прочитано) |
| 401 | `api_key_required` | нет `X-API-Key` или ключ неизвестен |
| 429 | `daily_topup_limit`, `too_many_attempts` | превышен дневной лимит (открытые оплаты учитываются) или слишком много оплат в минуту |
| 502 | `stripe_refused` | Stripe не открыл оплату (например, Managed Payments не включён или ключу не хватает прав); ничего не списано |
| 503 | `card_topup_unavailable`, `stripe_unavailable` | дверь закрыта (причина указана) или Stripe недоступен |

Webhook отвечает `{"received": true, "outcome": …}`: `credited`, `already_credited`, `pending`,
`refused` (суммы не сошлись — записано в лог как ошибка, ничего не зачислено), `expired`,
`disputed`, `refunded` или `ignored`.

### Таблица

`card_topups` (миграции 056 и 057): строка на каждую оплату — `topup_id`, `account_id`,
`amount_cents` (кредит), `charge_cents` (что платит карта без налога), `status` (`new` → `open` →
`credited` / `expired` / `failed` / `disputed` / `refunded`), `session_id`, `payment_intent`,
`livemode`, `credited_mc`, `tax_mode`, `tax_behavior`, `tax_cents`, отметки времени.

## Проверка в песочнице Stripe по шагам

Так дверь проверили 2026-10-20; повторите это перед боевым запуском и после смены налогового
режима. Настоящие деньги здесь не двигаются.

1. **Песочница.** Зарегистрируйтесь на stripe.com, все шаги активации (документы, банковский счёт)
   пропустите. В панели откройте песочницу — сверху будет плашка «Sandbox».
2. **Ограниченный ключ** только с *Checkout Sessions: Write*. Скопируйте и сохраните прямо из
   буфера, чтобы ключ не попал ни в чат, ни в терминал:
   `pbpaste > ~/.aimarket-stripe-test-key && chmod 600 ~/.aimarket-stripe-test-key`.
3. **Stripe CLI** — чтобы события песочницы доходили до хаба на вашем компьютере. Если Homebrew
   отказывает (устаревшие Command Line Tools), возьмите сборку для macOS из официальных релизов
   на GitHub и сверьте контрольную сумму с `stripe-mac-checksums.txt`. Затем `stripe login` и выберите
   **песочницу** (не боевой аккаунт и не старый «Test mode»).
4. **Webhook-секрет CLI:** `stripe listen --print-secret > ~/.aimarket-stripe-whsec`.
5. **Локальный хаб** с `AIMARKET_CREDITS_ENABLED=1 AIMARKET_CARD_TOPUP_ENABLED=1
   STRIPE_SECRET_KEY_FILE=~/.aimarket-stripe-test-key STRIPE_WEBHOOK_SECRET_FILE=~/.aimarket-stripe-whsec`
   (и проверяемым налоговым режимом).
6. **Пересылка событий:** `stripe listen --forward-to http://127.0.0.1:<порт>/ai-market/v2/stripe/webhook
   --events checkout.session.completed,checkout.session.async_payment_succeeded,checkout.session.expired,charge.dispute.created,charge.refunded`.
   `stripe trigger checkout.session.completed` должен показать `[200]`: подпись сошлась (с неверным
   секретом будет `[400]`).
7. **Оплата:** `POST /ai-market/v2/account/topup/card {"amount_usd": 5}` с ключом аккаунта; человек
   открывает `checkout_url` и платит картой `4242 4242 4242 4242`, срок — любая будущая дата, CVC — любой.
8. **Проверка:** CLI показывает `checkout.session.completed` → `[200]`; пополнение `credited`; в
   журнале аккаунта ровно одна строка `topup` для него. Затем `stripe events resend <evt_…>`: снова
   `[200]`, а баланс не меняется.
9. **По желанию:** спор картой `4000 0000 0000 0259` → пополнение становится `disputed`; возврат в
   панели → `refunded`.
