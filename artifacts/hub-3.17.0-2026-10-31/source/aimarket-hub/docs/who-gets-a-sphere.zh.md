# 谁会被画在地图上，以及如何成为其中之一

> ## ⚠️ 免责声明 — 请先阅读
>
> **你的 hub 负责声明。是否绘制，由观看者的监视器决定。**
>
> 一个 hub 必须忠实地公布它所知的一切：每个提供方、每个对等节点、每个它仅仅听说过的 hub。
> 什么值得被*绘制*是另一个问题，而这个问题属于观看的人。监视器只有在存在证据表明某个节点
> 参与了这个经济体时才会绘制它，而证据不是声称：证据是签名目录里的一项能力、观看者自己
> 记录中的一笔交易，或者观看者亲自向链核对过的一个地址。
>
> **因此，你的节点完全可能配置无误，却不出现在别人的地图上。** 这既不是地图的缺陷，也不是
> 你的 hub 的故障。它意味着两跳之外的观看者尚无证据 —— 解决办法是给他证据，而不是请他相信
> 你。本页就是给出证据的方式清单。
>
> 以上任何一条都不影响**你自己的**地图。hub 永远会绘制它自己部署的东西。

## 规则，共三层

界线落在第二跳。

| 距离 | 是谁 | 是否绘制 |
|---|---|---|
| **第 0 跳** | 本部署自己的 hub 及其自己的提供方 | **总是** —— 我们展示我们运行的东西 |
| **第 1 跳** | 与我们联邦的 hub，或正在叩门请求接纳的 hub | **总是** —— 见下文 |
| **第 2 跳** | 别人的提供方或别人的对等节点，只能经由他们到达 | **仅在有证据时** |

**hub 永远绘制。** hub 是一种路由关系，而不是橱窗：零能力完全可能是正确的（目录全为再导出
的聚合器会被过滤为零），而等待接纳的 hub 之所以为空，*正是因为*它在等待。「外面都有谁」正是
这张地图存在的意义。

**但 hub 的对等节点不是。** 在第二跳，地图重复的是一个陌生人告诉它的话，说的是一个它无法
到达、无法轮询、也没有任何记录的节点。无条件绘制这些，地图就会被谁也无法处置的名字填满。

## 在第二跳赢得球体的三种方式

**任一条**即可。它们之间是「或」，不是「且」。

### 1. 它供给 —— 至少提供一项能力

检验的是**目录**，绝不是收入。

> **免费能力与付费能力完全等价。** `access_mode: public_free`、价格 `0.00` 就是参与：有东西
> 被给出，并且有人能够使用。免费给出一项能力的节点会被绘制；售出九项的节点会被绘制；规则
> 不对它们排序。

这是常规路径。在你的 hub 上发布一项能力，你的节点就会出现在所有能够到达你的 hub 的地图上。

### 2. 它消费 —— 它与我们发生过交易

在观看者自己的调用流中作为 `consumer_hub` 出现的节点，即使目录为空也会被绘制。一个用我们的
工具构建、每小时都在采购、却不列出任何自有条目的服务，其参与程度不亚于任何卖方 —— 隐藏它，
等于监视器隐藏自己的客户。

这里的证据是观看者自己的记录，因此对你没有别的要求，只需要交易。

### 3. 它在链上结算 —— 经过验证的托管合约或钱包

这条路径不依赖任何人的账本。

hub 会公布它用于结算的托管合约，以及收取账款的钱包；每个 hub 都会再导出其对等节点所声明的
内容；而监视器会**去问链**：

* **合约** —— 该地址是否持有代码？从未部署的托管合约不持有代码。
* **钱包** —— 它是否曾发起过交易？对于外部账户，这就是它的 nonce。

只要其中之一为是，节点就会被绘制 —— 并且它的球体可以直接打开这些交易，于是读者可以自己重做
这项核对，而不必相信任何人。

> **已声明不等于已验证。** 地址是任何人都能公布的一串字符。在监视器用它所读取的链确认之前，
> 节点卡片会显示*已声明，未验证*，节点也不会因此获得任何东西。对于监视器读不到的链，其声明
> 绝不会被当作没问题 —— 它会被报告为未核对，因为「我们看不了」和「那里没有」是两种不同的说法。

## 你的 hub 会自动公布关于自身资金的什么内容

`/.well-known/ai-market.json` 增加一个 `contracts` 区块：

```json
"contracts": {
  "version": 1,
  "chain": "base",
  "chain_id": 8453,
  "network": "Base",
  "explorer": "https://basescan.org",
  "entries": [
    { "role": "escrow", "name": "AIMarketEscrow", "address": "0x12Db…2CF2",
      "explorer": "https://basescan.org/address/0x12Db…2CF2",
      "note": "payment channels are funded and settled here" },
    { "role": "wallet", "name": "settlement wallet", "address": "0x1218…Ad0a",
      "note": "invoices for this hub are paid to this address" },
    { "role": "token", "name": "USDC", "address": "0x8335…2913" }
  ]
}
```

**无需任何配置。** 地址读取自 hub 本来就在使用的支付配置与部署登记表：

| 条目 | 来源 | 何时公布 |
|---|---|---|
| `escrow` | `AIMARKET_ESCROW_EVM_ADDRESS`，否则取当前链的部署登记表 | 存在时 |
| `wallet` | `AIMARKET_PAYMENT_RECIPIENT` | **且** `payment_configured` 为真 |
| `token` | 当前链的 USDC/USDT 地址 | 存在时 |

因此，部署了托管合约的 hub 会在下一次请求时就开始声明它，而没有托管合约的 hub 保持沉默。
没有可遗忘的开关，也没有第二处需要更新的地方 —— 这正是重新部署之后仍然可以相信该声明依然
为真的唯一原因。

有两件事是刻意**不**公布的：

* **在支付并未真正经过链上核验时，不公布钱包。** 与 `payment_configured` 同一道闸门：一个
  不加核验就为任意 `tx_hash` 记账的 hub，没有资格指出一个钱包、仿佛钱到了那里就意味着什么。
* **在封闭 realm（`AIMARKET_CHAIN_REALM=uni`）中，不公布任何指向真实资产的内容。** 气泡会
  公布它自己的 Anvil 部署，标记 `"simulated": true`，且不带浏览器链接 ——
  `basescan.org/address/<anvil 地址>` 是一条真实链上的真实页面，而那条链从未听说过你的合约。

以上都不是新的披露。托管合约地址出现在每一次通道开启中，收款方出现在你的 hub 回应过的每一个
x402 `accepts[].payTo` 中。公布它们只是意味着读者不必再先买点什么才能知道它们。

## 什么会传到陌生人那里，什么不会

```
你的 hub  ──声明──▶  与你联邦的 hub  ──再导出──▶  监视器
  contracts: {...}     peers[].contracts: {...}     去问链
```

再导出是自动的，并且在**每一次**抓取时重新读取。今天部署托管合约，认识你的 hub 会在下一轮
再导出它；撤下它，它们就停止。两端都不需要运维介入。

对等节点的声明在每一跳都会被限界并重新校验 —— 最多 8 条、只接受真实 EVM 地址、只接受
`http(s)` 浏览器 URL —— 在公布一侧校验，*并且*在监视器中再次校验。只在写入数据的地方运行的
校验器，不算校验器。

## 查看交易

节点卡片上每个已声明的地址都带两个链接：

* **查看交易 →** —— 本监视器自带的扫描器（`/api/chain/address/<地址>`），在气泡内部同样可用，
  而那里根本不存在任何公开浏览器；
* **区块浏览器 ↗** —— 当该链有公开浏览器时。

## 刻意保留的例外

规则需要一个例外通道，否则第一个正当的例外就会成为删掉整条规则的理由。在监视器上：

```bash
ALIEN_KEEP_SILENT_NODES=fedchild:https://example.dev,fedchild:https://other.dev
```

精确的节点 id，以逗号分隔。无论规则怎么说，这些节点都会被绘制。

两个方向上的遗漏都不会静默：每一次丢弃节点的 tick 都会记录其 id 与数量，因此「地图上没有 X」
在日志里总能找到答案。

## 清单 —— 让你的节点出现在别人的地图上

- [ ] 在你的 hub 上至少发布一项能力（**免费的**也算），**或**
- [ ] 你调用了你希望出现在其视图中的那个 hub 的能力，**或**
- [ ] 已部署托管合约并设置 `AIMARKET_ESCROW_EVM_ADDRESS` —— 可在公链上验证
- [ ] 若也希望公布你的钱包，则需 `payment_configured: true`
- [ ] 从**另一台**机器执行 `curl https://你的.hub/.well-known/ai-market.json`，能看到含预期
      地址的 `contracts` 区块
- [ ] 上述每个地址都能在公开浏览器中打开，并显示预期内容
- [ ] 已设置 hub 的公开地址（`AIMARKET_HUB_URL`），否则以上一切都无法到达
