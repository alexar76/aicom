## Что проверено

- Локальный HISTOR: Python 3.12, SQLite и отдельный PostgreSQL 18, настоящие локальные сокеты и WARDEN sidecar. Основной прогон: 1 581 passed, восемь опциональных тестов чтения HF проверены отдельно с `datasets==4.8.5` в офлайн-режиме, все восемь прошли. Сканер: 5/5, закреплённый `@aimarket/warden@0.26.0` с ожидаемым хешем, Ruff чистый. Логи `pytest-*`, `scanner-*` и `ruff.log` лежат рядом.
- Публичный `main` HISTOR `82d513f`: [CI](https://github.com/alexar76/histor/actions/runs/43252794621) зелёный на Python 3.11 и 3.12 (SQLite, PostgreSQL, sidecar), сборка Docker и health прошли; [Pages](https://github.com/alexar76/histor/actions/runs/43261728143) зелёный. Утренние красные прогоны остановились на исправленном Ruff: семь сортировок импортов и один неиспользованный импорт.
- [Прод](https://histor.modelmarket.dev/health): PostgreSQL, приложение 0.7.0; регулярный обход продолжался. Последний полный обход 12 ноября завершился в 10:58 UTC с 8 000 попыток. На выборочной [записи MongoDB MCP](https://histor.modelmarket.dev/s/98388baf698e7bff) с 27 инструментами пересчитан дайджест, `/check` вернул подписанное `same`. Воспроизведены подпись головы, включение листа 1 878 879 и согласованность журнала `2 158 699 → 2 161 020` (`audit-label-and-consistency.log`). Это проверка конкретной записи и состояния журнала, не сверка всех наблюдений.
- [Контрольная точка 2 159 583](https://histor.modelmarket.dev/api/v1/log/checkpoint/2159583): отдельно проверены подпись HISTOR и четыре Ed25519-подписи свидетелей, ключи сверены с опубликованными (`verified-witnesses.log`). Список допуска — [staging Witness Network](https://raw.githubusercontent.com/transparency-dev/witness-network/main/lists/staging/log-list-10qps-4klogs.1). Это не проверка содержимого `tools/list` свидетелями.
- Исправления локальные: из README и Mermaid на пяти языках убраны быстро устаревающие оценки охвата. `/stats` показывает два разных показателя по API: `lastRun.registryEndpoints` — удалённые эндпоинты официального реестра за последний завершённый обход (43 236 в проверенном срезе), `targets.listed` — все записи текущего индекса, включая пакеты (99 159 в том же срезе). `/servers` говорит «записи», а главная подписывает `targets.pinned` как число целей с закреплённым набором, не число уникальных наборов. Для исторических замеров сохранена дата. В Chromium с различающимися данными API проверены главная, `/stats` и `/servers` на EN/RU/ES/FR/ZH; `histor-counts-browser.log`.

- Векторы [спецификации дайджеста](../../mcp-tool-set-digest/SPEC.md): Python, JavaScript и Go прошли все 68. Контракт HISTOR и WARDEN совпал по всем 68; проверенные отличия `extras` перечислены в `digest-vectors.log`. Пять значений на странице CrawlCheck перепроверены отдельно, это два входных примера.

Следующий автоматический прогон — 13 ноября около 12:00 UTC. Успешный прогон ScraperWatch после правки ещё не подтверждён.

## Очерёдность

1. Восстановить третью песочницу и проверить готовность observer на двух доступных. Это снижает риск неполного покрытия пакетов.
2. Локализовать шаг тайм-аута ScraperWatch, повторить сверку без изменения даты исходных данных и только затем обновить ветку с Wren. Разнести сбой двух методов в мониторинге, чтобы публикация CrawlCheck не скрывала сбой ScraperWatch.
3. Перед внешним переходом формата `extras` согласовать его с CrawlCheck. Повторно сверить крайние векторы (дроби, Unicode, ограничения), указать дату и версию в отчёте.
