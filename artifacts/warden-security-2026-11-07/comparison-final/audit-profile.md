# mcp-audit-scanner 0.28.0 comparison profile

The pinned PyPI release and all resolved dependency archives were installed inside a networked runsc setup container. Actual scans run network-none, with no API credentials, one fresh opaque server per case and unmodified package code. Node24.22.2/Python3.13.18 runtime image is pinned by immutable SHA256; pip's installation report records archive hashes. USER=LOGNAME=bench is supplied consistently because numeric UID501 has no passwd entry.

The bulk adapter invokes the native `run_scan_async(extra_paths=[fresh_config], connect=True, guardrail_drift=True)` with its default analyzers and full native static pipeline. Only the transport function `mcp_client.connect_and_enumerate` is replaced: the exact captured tools/list objects are validated through the installed MCP SDK `ListToolsResult`, then converted using the native `_tool_info` into `ServerEnumeration`. All native live-definition poisoning, cross-tool delegation, annotation contradictions, static analyzers, toxic-flow pass, bundled rules, scoring and registry/exploit data remain enabled as native defaults. This is definition analysis, not agent execution or tool calls. Optional online/API/LLM functionality is not enabled; the actual container has no network.

Each case has fresh HOME, cwd, one-server config, explicit per-case native rug-pull state, fresh analyzer instances and no baseline/lock state. Worker reuse changes process startup only; timeout30s retires the worker and records an error rather than a clean or missed attack. Blip historical work uses two workers under2CPU/1536MiB; Attested uses one under1CPU/768MiB. Base runs use one worker1CPU/768MiB on each host.

All findings and native errors remain in the raw rows. Definition findings include every runtime-server finding, every finding with a tool identity, and delegation/annotation/collision findings. Any such HIGH/CRITICAL is counted regardless of analyzer/category. Native SCAN-ERR/analyzer crashes and SDK/tool-list errors are coverage errors, never detection hits. Launch/config-only findings are retained separately; the opaque local Node replay launch, first-scan RUGPULL-000 baseline and local-command/community hygiene messages are outside the definition-classification measure. This is not the native CLI exit-policy measure. Lower-severity/advisory definition signals are reported separately rather than called misses.

Native state-path evidence matches by using the same fresh case state location. These sample checks are separate from the all-case engine scans; do not describe all18110rows as individual CLI transports.
