# Frozen definition comparison methods

Primary products are the actual published Warden npm0.23.0, mcp-audit-scanner0.28.0 with its MCP extra, mcp-shield1.0.4, @askalf/truecopy0.10.5 (redstamp0.7.5), and @roshan6335/mcpsentry0.1.5. Registry responses, integrity values, resolved lockfile and pip installation report are retained in comparison/receipts and comparison/runtimes. Published Warden is a verified npm tarball, not the earlier patched source17 baseline. Candidate19 package0.23.1-dev.20261107.1 and source18 are frozen supplemental experiments, not additional independent products.

Each primary product attempts18110 versioned whole-server catalog observations independently on each host:3177 base rows plus14933 HISTOR rows. The MCPTox projections overlap; neither the overall18110 nor the MCPTox2103 is an independent attack-trial denominator. Report each cohort separately. HISTOR and public package catalogs are unlabelled: alert rates are not false-positive rates. All14933 historical versioned rows are executed independently, including484 repeated toolset digests;14449 distinct digests/272657 tool records are input provenance, not substituted execution counts.

Inputs are frozen file-backed JSON, with common supplied opaque c+32hex wire IDs and per-file SHA256. Gate-visible configuration/server names/filenames contain no package names, truth labels or split names. Original tool names/descriptions/schemas remain unchanged within each declared projection. The catalog toolsSha256 is Python sorted JSON provenance, not JCS; toolsFileSha256 checks exact physical input bytes. No historical package implementation or upstream MCPTox Python is executed. Each input case preserves the entire toolset so native cross-tool logic is retained; cross-server multi-catalog attacks are outside this one-server design.

All engines run unmodified in runsc network-none containers. No ports, host networking, credentials or Docker socket are exposed. Read-only root, nonroot501:501, cap-dropALL, no-new-privileges and isolated tmpfs are used; source/runtime/data mounts are read-only and only dedicated results are writable. Node comparators use1CPU/768MiB each. Audit HISTOR uses Blip2CPU/1536MiB/two workers and Attested1CPU/768MiB/one worker. Comparison runtime image SHA256 db7085498187e8477fa462d5f1652d62bdf4b8af29ea3666bd1748a8315631a5 contains Node24.22.2/Python3.13.18. Resource restrictions are configured and Linux cpu.max/memory.max also checked; cross-host timing is not a controlled speed comparison.

Bulk execution uses native engines with fresh independent per-case state, rather than thousands of process startups. Representative actual CLI/MCP checks validate these routes. Shield uses its native four analyzers and exact scanner assembly after its own SDK ToolSchema/cacheToolMetadata checks. Sentry uses its native scanText and exact text/hash/snippet assembly: its native scanServer uses a custom JSON-RPC client, not the MCP SDK, and legitimately accepts some definitions that Shield's SDK rejects. Truecopy uses native scanSkill/gateTools/inspectServer with fresh blocked/allowed/listed state and an empty cold lock; native proxy checks wait for tools/list before ending stdin. Warden uses native listAllTools validation and a fresh Warden/ThreatFeed/empty PinStore per case; policy is blockAtSeverity=high, sensitiveToolPatterns=[], allowUnknownServers=true, pinToolDefs=true. The mcp-audit full native pipeline and transport-only capture substitution are detailed in audit-profile.md.

The primary metric is definition-related HIGH/CRITICAL findings, with lower-severity/advisory-only signals separately counted. Warden includes both static-scan and threat-feed definition gates. Unpinned/origin/launch-hygiene policy findings remain in raw records but are outside this metric. Any unknown Warden gate requires review. Any-definition and high-definition counts are whole-case booleans; advisory-only=any-high, not the number of cases with any lower finding (which can overlap high). Analyzer crashes, native schema rejections, partial-analysis limits and timeouts are coverage outcomes, never clean cases or misses; their raw findings remain available. Native enforcement is distinct: Warden allow=false is retained, Truecopy poisoned/unpinned cold-lock refusals are separate, Sentry CLI exits1 only for critical rules, and Shield normally exits0 even when it reports vulnerabilities.

Corrections to the harness are retained as separate source/attempt evidence: numeric UID username setup, audit INFO state-path evidence, Warden static-only normalization corrected to include threat-feed, a combined API+native parity deadline corrected for the maximum-byte case, response-aware Truecopy parity pipe lifetime, and ASCII-safe logging for Sentry's native lone-surrogate snippet. Completed Sentry rows were preserved byte-for-byte when logging resumed. No detector rules or frozen input definitions were changed based on these comparison results.

Final cross-host verification is case-level, not inferred from counts: compare every key, opaque identity, exact input-file SHA256, product version/source identity/runtime image, status, high/any/advisory booleans and canonical full native result signatures. Only audit's own temporary config finding_path and fresh RUGPULL-000 state-file evidence are normalized. Every core finding text/code/severity remains represented in the signature. Error/timeouts are paired separately and excluded from complete-verdict comparisons. Both raw and derived reports remain remote; all actual runtime work is remote, and no local project interpreter/build/test/cache/server was used in this expanded comparison.

Candidate19 was developed post hoc after earlier observed MCPTox failures. Its supplied dev/test split must not be described as independently held out for that repair. This latest all-product comparison froze the candidate before its executions; published-product results and the posthoc candidate remain separate rows. Static definition classifications are not end-to-end agent attack-success or containment measurements.

Truecopy classifies any content finding, including advisory severity, as poisoned and withholds that tool. With no matching lock it also withholds otherwise unflagged tools as unpinned. Common HIGH/CRITICAL is therefore not Truecopy's full withholding rate. The grouped nativeBlocked metric applies only to Warden native allow=false; it is null for report-only products and Truecopy, whose enforcement mapping is separate. Figures must use HIGH/CRITICAL signal and advisory-only signal labels, not a universal blocked label.

The single actual Blip Shield API timeout was HISTOR p03897. This is distinct from p05122, the maximum-byte case whose initial combined API+native parity budget expired and whose single90scombined parity retry subsequently matched. Actual scan deadlines stayed30s.
