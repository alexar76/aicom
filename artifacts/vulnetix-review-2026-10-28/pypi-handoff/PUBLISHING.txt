ПОДГОТОВКА
Можно взять актуальный checkout Gitea и перейти из корня репозитория:
  cd artifacts/vulnetix-review-2026-10-28/pypi-handoff
Либо распаковать pypi-publication-handoff.zip и открыть папку pypi-handoff.
Контрольная сумма архива находится в соседнем pypi-publication-handoff.zip.sha256.
Для проверки нужен Python 3.9+ со стандартной библиотекой; для установки всех
восьми пакетов вместе нужен Python 3.11+. Для отправки нужен uv.
Использовать полномочия издателя пакетов экосистемы alexar76.
Не пересобирать wheels и не брать dist/* из соседних проектов: передаются
конкретные проверенные файлы из wheels/.

ПРОВЕРКИ БЕЗ ПУБЛИКАЦИИ
  python3 publish_prepared.py
Это только локальная проверка; сеть и credentials не используются.
  python3 verify_release.py --availability --report availability.json
Это только публичные GET к PyPI: свободны ли точные версии, а если уже заняты,
совпадают ли имя файла, размер и SHA-256. Конфликт означает остановку.

ПУБЛИКАЦИЯ — ВЫПОЛНЯЕТ ТОЛЬКО НАЗНАЧЕННЫЙ ИЗДАТЕЛЬ
Издатель предоставляет UV_PUBLISH_TOKEN через свой обычный способ хранения
credentials. Не записывать значение в этот архив, исходники, отчёты или чат.
  python3 publish_prepared.py --upload-to-pypi
Эта команда повторяет проверки, загружает восемь конкретных wheels по порядку
в https://upload.pypi.org/legacy/ и затем выполняет проверку опубликованных
файлов. GitHub, Gitea, git tags и deployment эта команда не изменяет.
Sdist в этом пакете передачи нет: проверялись и передаются только wheels.

ПРОВЕРКА ПОСЛЕ ПУБЛИКАЦИИ (МОЖНО ЗАПУСТИТЬ ОТДЕЛЬНО)
  python3 verify_release.py --published --report published-verification.json
Проверяются точные версии через публичный JSON API PyPI. Wheel скачивается с
files.pythonhosted.org; его SHA-256 должен совпасть и с PyPI, и с манифестом.
Проверяются все Python-файлы, обязательные модули исправлений и RECORD.
Скачанный код не устанавливается и не исполняется.
Успех: восемь статусов published_verified, итог PASS и exit code 0.
not_published или error означают, что проверка ещё не завершена. При задержке
появления файлов повторить только эту команду; не менять версии и не выполнять
повторную загрузку вслепую. При частичном выпуске повторный запуск издателем
пропускает только уже совпадающие файлы; конфликтующий релиз блокируется.

ЧТО СООБЩИТЬ ПОЛЬЗОВАТЕЛЯМ
HTTP в MCP/Metis/Treasury/Platon по умолчанию требует ключ даже с localhost.
Явный *_LOCAL_RELAY=1 доверяет локальному TCP, включая прокси того же пользователя.
Без таблицы сокетов Linux дополнительно нужен *_LOCAL_UNVERIFIED=1.
Предпочтителен ключ; проверки production и настроенного ключа сохраняются.
MCP stdio не изменён. Пауза входа SKOPOS теперь относится к конкретной попытке:
чужие ошибки не продлевают её ожидание. Trusted proxy lists по умолчанию loopback;
LOGOS по умолчанию слушает 127.0.0.1; проверка SSH-ключей включает короткие имена.
Для установки проверенного набора после публикации:
  python3 -m pip install --upgrade -r requirements-security.txt

САМОПРОВЕРКА ИНСТРУМЕНТОВ (опционально, нужен pytest)
  python3 -m pytest test_handoff.py -q
15 тестов проверяют контрольные суммы, RECORD, конфликты версий, повреждённые
скачивания и то, что режим подготовки не читает credentials и не публикует.
Сетевые ответы и отправка в этих тестах подменены; реальных загрузок нет.

ПОВТОРНАЯ ПОДГОТОВКА ИЗ НОВОГО КОММИТА (из корня репозитория)
  .venv/bin/python scripts/prepare_security_pypi_handoff.py
Это офлайн-сборка восьми wheels с проверкой Python-файлов против git show HEAD.
Она обновляет манифест и архив. Перед передачей повторно запустить профильные
тесты и --availability. Для упаковки после обновления отчётов:
  .venv/bin/python scripts/prepare_security_pypi_handoff.py --bundle-only
Номера версий должны быть свободны в PyPI. Публикации эта подготовка не делает.
