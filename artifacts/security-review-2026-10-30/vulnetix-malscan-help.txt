Scan a project's locally-installed dependencies for malicious code, run
entirely on the bytes on disk with the malscan-engine — no dependency on the
backend's periodic pipelines.

Four detector families run over each ecosystem's install/cache locations:
  • iocscan  — STIX IOC filesystem scan (known-bad domains/IPs/URLs in text and
               extracted binary strings), with file + line + context evidence
  • detect   — manifest / install-script pattern + shell-obfuscation detectors
  • ioc      — indicators of compromise extracted from manifests/scripts
  • badhash  — known-bad artifact-hash blocklist over declared/candidate hashes

Scan targets are resolved per ecosystem (npm node_modules, python site-packages,
go vendor, rust/cargo, ruby, php, java, dotnet, dart, elixir). User-scoped/home
caches (~/.npm, ~/go/pkg/mod, ~/.cargo, ~/.m2, …) are scanned only with
--include-home. --include-system scans the whole machine instead of one
checkout: machine-wide installs (/usr/lib/python3*/site-packages,
/usr/lib/node_modules, system gems, /usr/share/java, …), the caches in every
account's home, and the system binary directories (/usr/bin, /usr/local/bin,
/opt, …). --system-root points it at a mounted volume, an unpacked image or
/proc/<pid>/root instead of the running system.

Evidence is SARIF, always written to .vulnetix/malscan.sarif (override with
--output-file) and uploaded to Vulnetix when authenticated. The terminal output
format is set by -o (pretty by default). Exit status is non-zero when malware is
found.

Findings are tracked in .vulnetix/memory.yaml. A finding the engine no longer
reports is marked resolved and attested in .vulnetix/vex-malscan.openvex.json.
Pass --disable-memory to turn this off.

Threat-intel definitions: the engine ships an embedded bad-IP/host/email
blocklist aggregated from public feeds. Run "malscan --fetch-definitions" to
refresh those definitions at runtime (downloaded to a local cache dir); every
subsequent scan layers them over the embedded set, so you stay current between
engine releases without recompiling. Pass --feeds with --fetch-definitions to
use a custom feeds.json source/parser mapping for the badnet blocklist refresh.

Examples:
  vulnetix malscan                       # pretty findings; writes .vulnetix/malscan.sarif
  vulnetix malscan ./app -o json         # detections as JSON
  vulnetix malscan --include-home        # also scan ~/.npm, ~/go/pkg/mod, …
  vulnetix malscan --include-system      # the whole machine: system installs, every home, /usr/bin, /opt
  vulnetix malscan --include-system --system-root /proc/1234/root   # a running container's filesystem
  vulnetix malscan -o sarif              # print SARIF to stdout (still saved + uploaded)
  vulnetix malscan --no-ioc-feeds        # skip the STIX network fetch (detect/badhash only)
  vulnetix malscan --fetch-definitions   # refresh local threat-intel definitions, then exit
  vulnetix malscan --fetch-definitions --feeds ./feeds.json

Usage:
  vulnetix malscan [path] [flags]

Flags:
      --catalog string       Directory of malscan capability config overrides (sets MALSCAN_CONFIG_DIR)
      --feeds string         Path to a badnet feeds.json source/parser mapping for --fetch-definitions
      --fetch-definitions    Fetch ALL threat-intel feeds fresh (badnet blocklists + vulnetix STIX index + TweetFeed) and rebuild local malscan definitions (no scan); subsequent scans use them
  -h, --help                 help for malscan
      --include-home         Also scan user-scoped/home install caches (~/.npm, ~/go/pkg/mod, ~/.cargo, …)
      --include-system       Scan the whole system: machine-wide installs, every account's caches and the system binary directories
      --max-file-size int    Skip files larger than this many bytes (default 10485760)
      --no-binary-analysis   Do not extract/match IOCs in binary files
      --no-ioc-feeds         Skip the STIX IOC filesystem scan (no network); run only detect + badhash
      --no-upload            Do not submit findings to Vulnetix (submitted automatically when authenticated)
  -o, --output string        Terminal output format: pretty (alias: table), json, sarif (default "pretty")
      --output-file string   Path to write the SARIF report (default: <path>/.vulnetix/malscan.sarif)
      --path string          Directory to scan (defaults to CWD; resolves to the git root) (default ".")
      --scan-depth int       Max directory depth per target (0 = unlimited)
      --system-root string   Filesystem --include-system describes: a mounted volume, an unpacked image or /proc/<pid>/root (default "/")

Global Flags:
      --disable-memory   Disable memory file reads/writes. For users who do not use the Claude Code Plugin or for debugging. VDB commands will skip memory-related side effects when set.
      --no-analytics     Disable anonymous usage analytics
      --no-banner        Suppress the Vulnetix startup banner
      --no-progress      Suppress progress indicators
      --org-id string    Organization ID (UUID) for Vulnetix operations
      --silent           Suppress all log output, only print final result
  -v, --verbose count    Show more detail: -v adds diagnostics (rate limits, cache status, auth notes) and per-advisory version checks; -vv adds the raw evidence
