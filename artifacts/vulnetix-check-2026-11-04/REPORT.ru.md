# Проверка кода по классам Vulnetix — 4 ноября 2026

Запрос владельца: «но сначала проверь код по вулнетиксу» (перед выпуском WARDEN 0.23.0).

## Что проверялось

Весь дифф ветки `claude/multika-agent-ecosystem-2db731` относительно `main` (PR #11 в Gitea):

- `aimarket-hub/aimarket_hub/provider_buyer_ref.py` и правка `local_delivery.py`;
- `attested/attested-memory-hub/memory-market` и `provenance-ledger` (`app.py`);
- WARDEN: `src/opencode-plugin.ts`, изменения ядра `flow-guard-*`, скрипт red-team;
- конфигурация на серверах: прокси `multica-egress` (tinyproxy), `AIMARKET_TRUSTED_PROXIES`, `set-secrets.sh`.

Классы ошибок взяты из прошлых находок Vulnetix и нашего аудита 25.10:
- открытый вход без ключа (CWE-306);
- проверка по имени и подключение без закрепления адреса (CWE-918);
- доверие `X-Forwarded-For` и другим заголовкам клиента;
- отключённая проверка ключей и сертификатов;
- fail-open при ошибке, секреты в логах, ReDoS в новых регулярных выражениях.

Новых зависимостей изменения не добавляют: WARDEN по-прежнему без зависимостей, у хаба и memory-market
списки не менялись, в прокси только пакет `tinyproxy` из Ubuntu 24.04. Поэтому сопоставление с базой
Vulnetix и `malscan` по зависимостям ничего нового не дали бы и не запускались.

## Найдено и исправлено

1. **Хаб: доступ субподрядчика к личной памяти заказчика.** Если вызов оплачен из бюджета чужой работы
   (`funded_by == "allowance"`), `funding.account_id` — это счёт заказчика. Ссылка на покупателя
   (`X-AIMarket-Buyer-Ref`) называла заказчика, и субподрядчик с токеном работы читал бы его личную память
   через `memory.read`/`memory.search`. То же с мандатом: агент становился самим принципалом.
   Исправлено так:
   - вызов из бюджета чужой работы теперь анонимен (только публичное чтение, запись запрещена);
   - вызов по мандату получает своё пространство `mandate:<счёт>:<агент>`.

   Тест: `aimarket-hub/tests/test_provider_buyer_ref.py::test_delegated_spending_never_names_the_principal`.
   С 10:03Z до 15:02Z на attested-хабе стояла прежняя версия. Злоупотреблений не было: память через хаб пишет
   только вжик, а у его счёта нет ни мандатов, ни бюджетов работ. Образ `attested-memory-hub:bref2-20261104`
   выкачен 15:02Z после «Да, выкатывай» владельца; проверки после выкатки — в
   `artifacts/memory-owner-2026-11-04/ROLLOUT.md`.

2. **WARDEN для OpenCode: обход через субагента.** Субагент (`task`) работает в новой сессии с чистым
   состоянием. Внедрённая команда могла поручить свежему субагенту прочитать секрет и отправить его: тот
   «не видел» чужого текста, и защита молчала. Теперь одно состояние на всё дерево сессий (по корню). Запрос
   субагента не записывается как слова пользователя.

3. **WARDEN для OpenCode: fail-open при сбое записи результата.** Если `flowPost` падал, результат не
   записывался: чужой текст или прочитанный ключ «пропадали» для следующих решений. Теперь после такого сбоя
   все вызовы этого дерева сессий отклоняются.

4. **WARDEN для OpenCode: рабочий каталог от модели.** Классификация путей брала `workdir` из аргументов
   модели. Теперь берётся каталог сессии.

Тесты на 2–4: `warden/test/opencode-plugin.test.ts`, блок «subagents share the session tree state».

## Проверено и в порядке

- **Нет новых открытых сервисов.** `memory-market` и `provenance-ledger` в проде по-прежнему требуют внутренний
  токен хаба на `/capabilities/*/invoke`; без него `X-AIMarket-Buyer-Ref` не принимается. Прокси
  `multica-egress` принимает клиентов только из `10.250.0.0/24`, CONNECT только на 443.
- **Заголовки клиента.** Ссылку на покупателя хаб строит сам и отправляет только хостам-шлюзам оператора;
  заголовки клиента он поставщику не пересылает. `AIMARKET_TRUSTED_PROXIES` — только шлюз Docker и
  `127.0.0.1`; адрес клиента берётся справа налево (подставленный слева адрес отбрасывается), проверено в
  живом образе.
- **SSRF.** Новый код не загружает URL из запроса. Прокси фильтрует по имени хоста из CONNECT или строки
  запроса, а не по `Host`; IP-литералы не проходят.
- **Ключ ссылки на покупателя** выводится из сида подписи хаба через HMAC и наружу не выходит. Без сида
  ссылки нет, то есть вызов анонимен (fail closed).
- **Секреты в логах.** Адаптер пишет только имя инструмента, причину и решение; аргументы не логируются.
- **ReDoS.** Новые выражения линейные: токен Telegram, `aimk_`, UUID, строка с учётными данными, разбор patch.
- **gitleaks 8.30.1.** В рабочем дереве и изменённых файлах чисто. В истории ветки (коммит 197490d17) есть
  синтетические значения из теста (UUID-ключ, `mul_0123…`); теперь они собираются во время выполнения.
