# Expert Memory Market 使用场景

当 buyer 需要 actionable answer，同时必须在 unlock 前检查 authorship、evidence
与 price 时，本 market 最具价值。

## Source-bound research brief

**对象。** Analyst、research team 与专业媒体。

**任务。** 在不公开完整付费 brief 的情况下出售结论与方法。Summary、
`source_refs`、Truth、Provenance 可供购买前评估。

**推荐路径。** 单篇作者收益使用 per-read；探索 collection 使用 pass。

## Incident remediation library

**对象。** SRE、security responder、managed service provider。

**任务。** 将已验证 remediation 转换为 machine-readable Memory Unit。Agent 按
symptom 搜索，排除 contested entry，并只购买所需 runbook。交付失败释放 reserve。

**推荐路径。** 带 allowed publisher / Truth policy 的 per-read。

## Autonomous agent 的 premium context

**对象。** Research、coding、procurement、support agent operator。

**任务。** 无需把整个 corpus 复制进 prompt 或 vector store 即可使用外部 expertise。
将 listing、rank reason、charge、receipt 与最终 output 一起保存。

**推荐路径。** Public discovery + 带 spend cap 的 per-read。

## Due diligence / compliance intelligence

**对象。** Legal、investment、vendor-risk、compliance team。

**任务。** 同时购买 claim 与 evidence trail。Listing lineage 用于判断相关性，
paid access unlock 详细分析。新 evidence 会更新 Truth。

**推荐路径。** Active review 使用 pass；外部专家意见使用 per-read。

## Advisory / implementation playbook

**对象。** Consultant、architect、专业 agency。

**任务。** 提供 context、constraint、failure mode、source、next action，而不是
static PDF。结果可以直接进入 agent workflow。

**推荐路径。** 单个 playbook 使用 per-read；限时 engagement 使用 pass。

## 已评估的 prompt、policy 与 handoff

**对象。** Agent builder 与 AI platform team。

**任务。** 出售带 evaluation context 的 operating policy。Provenance 显示 origin，
Truth 区分 tested / contested / rejected version。

**推荐路径。** Versioned asset 使用 per-read，并明确 cache policy。

## 不应在此出售

- Wallet secret、API key、seed phrase 或 credential。
- 没有合法 policy 的 personal / regulated data。
- 被模糊 summary 掩盖的 unsupported claim。
- 可从引用 public source 直接获得的普通文档。
- 被描述为 time-bound entitlement 的 perpetual access。

从一个狭窄 category 开始，并遵循[实施指南](MARKET_GUIDE.md)。
