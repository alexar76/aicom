# Сценарии использования

Attested Memory нужен там, где **забывать дорого**, а **слепое доверие ещё
дороже**. Ниже — ситуации, в которых заметки, чаты и «похожий» векторный поиск
недостаточны: нужны идентичность, truth state, provenance и точный settlement.

Имена маршрутов, заголовки и платёжные условия на всех языках остаются точными.
Локализуется только пояснительный текст.

## Второй мозг основателя, который переживает context rot

**Кто.** Основатель, исследователь или оператор, который каждый день прыгает
между инструментами, агентами и устройствами.

**Проблема.** Решения живут в чатах, выгрузках Notion и недописанных промптах.
Через шесть недель никто не может сказать, *почему* выбран путь, каким
источникам доверяли и какой агент придумал удобный пересказ.

**Как работает.**

1. Запишите Memory Unit с решением, обоснованием, тегами и `source_refs`.
2. Подпишитесь как actor (`X-Actor-ID` / public key / signature). Приватный
   ключ остаётся в клиенте.
3. Позже ищите через `/memory/api/search` и проверяйте truth + provenance,
   прежде чем использовать память в новом плане или агентном прогоне.

**Зачем attestation.** Вы достаёте не «похожий абзац», а переносимое
утверждение с автором и родословной.

**Старт.** [Personal Memory](/memory) · [Руководство](USER_GUIDE.md) · trial на
[/billing](/billing).

## War-room инцидента, где след решений не теряется

**Кто.** On-call инженеры, SRE, security responders.

**Проблема.** Инцидентный канал быстрее wiki. Постмортем пишут по памяти,
авторство решений размыто, а через неделю агент повторяет отклонённый
митигацион, потому что в общем namespace ничего не было подписано.

**Как работает.**

1. Откройте Team Memory OS и создайте team namespace.
2. Участники пишут заметки, отклонённые варианты и финальные действия с
   actor-подписью.
3. Gateway проверяет membership; Hub принимает только записи
   `team:<id>`. Запросы не протекают в чужую команду.

**Зачем attestation.** Handoff становится аудируемым. Offboarding отзывает
ключ; короткоживущие team assertions истекают без криминалистики по чатам.

**Старт.** [Team Memory OS](/teams) · [Руководство § Teams](USER_GUIDE.md).

## Экспертное знание, которое продаётся без утечки корпуса

**Кто.** Эксперты, research-шопы, advisory-бутики.

**Проблема.** Открыть корпус бесплатно — убить бизнес. Показать только тизер —
убить доверие. Покупателю нужно provenance до оплаты; продавцу — доступ на
срок, а не вечная копия по умолчанию.

**Как работает.**

1. Опубликуйте Memory Unit с публичным summary и платной видимостью тела.
2. Покупатель ищет каталог, смотрит truth/provenance и открывает точный
   USDC-инвойс на Base.
3. KOVA подтверждает перевод; Gateway выдаёт scoped entitlement. Доступ
   заканчивается вместе с планом.

**Зачем attestation.** Discovery честный. Settlement точный. Entitlement —
криптографический scope продукта, а не PDF «по честному слову».

**Старт.** [Expert Memory Market](/market) · [Оплата](/billing).

## Multi-agent handoff с криптографической непрерывностью

**Кто.** Операторы агентов, orchestration-команды, автономные workflow.

**Проблема.** Агент A отдаёт чат-summary агенту B. Summary не подписан,
частично галлюцинирован и без источников. Сбой списывают на «глупую следующую
модель», хотя пропал provenance.

**Как работает.**

1. Агент A пишет подписанный handoff: ограничения, инструменты, источники,
   открытые риски.
2. Агент B читает его по той же actor/team политике и проверяет provenance
   до продолжения.
3. Truth state едет вместе с unit — противоречия видны, а не сглажены в
   уверенный текст.

**Зачем attestation.** Непрерывность — свойство записи, а не того, у кого
осталась вкладка.

**Старт.** [Developers](/developers) · [Руководство § Actor](USER_GUIDE.md).

## Due diligence и исследование с claims, привязанными к источникам

**Кто.** Аналитики, юристы, investment и vendor-review команды.

**Проблема.** В заметках фигурируют «дек», «созвон» и «что-то из Slack». Когда
claim оспаривают, цепочка хранения — это ощущение.

**Как работает.**

1. Каждое существенное утверждение — Memory Unit с явными `source_refs`.
2. Truth state обновляется по мере поступления доказательств.
3. Позже файл собирается из provenance receipts, а не из реконструированного
   фольклора.

**Зачем attestation.** Спорят о claim и evidence, а не о том, чьи заметки
«свежее».

**Старт.** Personal или Team · [Глоссарий](GLOSSARY.md).

## Автооплата, когда браузер уже закрыт

**Кто.** Покупатели из wallet-приложения, скрипты settlement и операторы,
которые не сидят на вкладке checkout.

**Проблема.** Классический checkout умирает с закрытием вкладки. Ручной
«вставь tx hash» плодит саппорт и двусмысленные частичные платежи.

**Как работает.**

1. `POST /v1/billing/orders` с уникальным `Idempotency-Key`, планом и payer.
2. Отправьте точную сумму canonical USDC на Base получателю инвойса.
3. KOVA сверяет token, payer, recipient, amount и глубину подтверждений.
4. Gateway активирует ключ автоматически. Poll
   `GET /v1/billing/orders/{id}` с checkout token вернёт ключ после
   confirmed — даже если исходная сессия браузера исчезла.

**Зачем attestation.** Движение денег и выдача entitlement связаны тождеством
инвойса, а не скриншотом кошелька.

**Старт.** [Billing](/billing) · [Руководство § Покупка](USER_GUIDE.md).

## Безопасный offboarding без сиротской институциональной памяти

**Кто.** Тимлиды, security, IT.

**Проблема.** Уходящий оператор уносит чат-экспорты и личные заметки с
настоящими runbook. Отозвать Slack ≠ отозвать знание, которое никогда не
жило в контролируемой системе.

**Как работает.**

1. Держите операционное знание в Team Memory OS в явном namespace.
2. При уходе немедленно rotate/revoke SaaS-ключ.
3. Team assertions истекают за минуты; Hub по-прежнему требует actor proofs
   на защищённые read/write.

**Зачем attestation.** Доступ кончается как событие control plane, а не как
надежда, что кто-то почистил Drive.

**Старт.** [Team Memory OS](/teams).

## Для чего это не подходит

- Общий архив чатов без дисциплины идентичности и источников.
- Хранение private keys, seed phrases или сырых credentials.
- Безграничный «share with the world» без visibility policy.
- Округлённые crypto-платежи — точная сумма USDC и есть номер инвойса.

Если workflow терпит тихую потерю авторства, источников и финальности оплаты —
хватит блокнота. Если нет — начните с нужного product surface и держите
контракты Hub точными.
