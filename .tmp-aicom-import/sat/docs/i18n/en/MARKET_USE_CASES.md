# Expert Memory Market use cases

The market is strongest when the buyer needs an actionable answer but must
inspect authorship, evidence and price before unlocking it. These patterns use
the contracts that exist today: keyless listings, pass access, metered reads,
publisher splits and verifiable receipts.

## Source-bound research brief

**Who.** Analysts, research desks and specialist newsletters.

**Job.** Sell the conclusion and method without giving away the entire paid
brief. Publish a useful summary, explicit `source_refs`, Truth state and
Provenance. The buyer inspects that evidence, then uses a pass or pays per read.

**Best path.** Per-read when one brief should pay its author; Expert Pass when a
buyer is exploring a collection.

## Incident remediation library

**Who.** SRE teams, security responders and managed service providers.

**Job.** Turn proven remediation steps into machine-readable Memory Units. An
agent searches by symptom, rejects contested entries and buys the precise
runbook only when needed. A failed upstream retrieval releases the reserved
charge.

**Best path.** Per-read with strict allowed publishers and Truth state policy.

## Premium context for autonomous agents

**Who.** Operators of research, coding, procurement and support agents.

**Job.** Give an agent access to external expertise without copying an entire
corpus into its prompt or vector store. Persist listing ID, rank reasons, charge
and provenance receipt with the final output.

**Best path.** Keyless discovery plus per-read authorization under a spend cap.

## Due-diligence and compliance intelligence

**Who.** Legal, investment, vendor-risk and compliance teams.

**Job.** Buy a claim together with its evidence trail. The public listing shows
enough lineage to judge relevance; paid access unlocks the detailed analysis.
If later evidence changes the Truth state, future ranking reflects it.

**Best path.** Expert Pass for an active review window; per-read for externally
commissioned specialist opinions.

## Advisory playbooks and implementation patterns

**Who.** Consultants, architects and specialist agencies.

**Job.** Package a narrow decision pattern rather than a static PDF: context,
constraints, failure modes, source links and recommended next action. Buyers can
inspect the provenance before paying and integrate the result directly into an
agent workflow.

**Best path.** Per-read for individual playbooks; a pass for a time-boxed client
engagement.

## Evaluated prompts, policies and agent handoffs

**Who.** Agent builders and AI platform teams.

**Job.** Sell a tested operating policy or handoff template with its evaluation
context. Provenance shows origin and lineage; Truth state distinguishes tested,
contested and rejected versions.

**Best path.** Per-read for versioned assets, followed by a local receipt and
explicit cache policy.

## What not to sell here

- Wallet secrets, API keys, seed phrases or raw credentials.
- Personal or regulated data without a lawful disclosure and retention policy.
- Unsupported claims disguised by a vague public summary.
- Commodity documents that a buyer can obtain from the cited public source.
- Perpetual corpus access represented as a time-bound entitlement.

Start with one narrow category, publish enough evidence to support a buying
decision, and follow the [implementation guide](MARKET_GUIDE.md).
